### 报告化与可核验（0.16 / 0.17 / 0.18 / 0.20 新增）

- **影子盘 ID**：工具参数 `shadow: true`（面板与独立页默认开启）为结果生成 `LY-XXXXXXX` 短 ID。同一组归一化参数——键序无关、默认值等价、地址与等值经度等价——在任何机器上得到同一 ID；`baseId` 不含版本，`id` 含版本。面板可一键复制，同一 `baseId` 重排时自动与本地上一张盘比对，版本升级或字段变化会展开列出根因（如「时柱 甲子 → 壬辰」）。塔罗 / 六爻未给 `seed` 时把实际牌面 / 六爻值算进 ID，不把两次不同的抽牌误认成同一张盘

- **人元司权**：按「节」到出生日的日差，算出本月第几日、哪一藏干当权（30 日表：余气 → 中气 → 本气；节当日为第 1 日，第 31 日以后按本气并标出）。另有 7/7/16、9/3/18 等分法，结果里只列本插件口径；三命通会卷二「论人元司事」此本又作寅月 5/5/20、卯月 7/23，原文随该节并列、不改取格。司权表比本柱藏干表宽（子月壬、卯月甲、午月丙、酉月庚、亥月戊只出现在司权表里），两表各照原样。分日只作解释层的一层细节，取格仍按本气、透干与会支判定，不随轮值改判

- **十六型人格 `mbti`**：一份 **MBTI 风格**的 24 题问卷（四维度各 6 题，李克特 1–5 计分，按维度净分取字母、平手取 I/N/F/P 并标「临界」），先不带 `answers` 调一次拿到题目，再把 24 个分数按顺序传回来；结果给四维强度（临界/轻微/明显/很强）、类型称号与关键词、优势与留意、认知功能栈（主导 → 辅助 → 第三 → 劣势）、工作/关系/学习/课题四段白话。**不是官方 MBTI 量表**（未用其题目、常模与评鉴许可），只作自我参照，不用于招聘、晋升或诊断；跳过某题传 `null`，答满 12 题即可出口径。面板与独立页把这 24 题做成 4 题一页的分页问卷（1–5 单选 + 进度条 + 上一页/下一页），答案按题序交给 `answers`。
- **起名 `name`**：391 字自建字库（常用名用字，按五行分段，每字带**拼音/声调/康熙笔画**），评估时**逐字**给五行、释义、来源与是否合喜用，未收录的字不猜五行但给**同喜用五行的可换字**（也可用 `charElements` 自行指定）；**五格剖象**按康熙字典繁体笔画算天格/人格/地格/外格/总格，配通行本 81 数理（超 81 按 −80 回绕）与三才五行，任一字缺笔画就整体返回「算不了」并点名缺哪个字，可用 `strokeOverrides`（逐字）/`surnameStrokes`（按姓）补；**音韵**只做机械检查——全名同调、相邻同声母/同韵母、叠字撞音，判「顺口/略拗/拗口」，**不做语义谐音**；生成候选名按「合喜用 → 两字异行 → 五格格数 → 性别倾向 → 字库序」排序，只是排序不是「吉名」判定

### 解析与详解（interpret）
每个体系的排盘结果下方都会跟一个「解析与详解」模块，帮你把盘面翻译成能看懂、能照着做的事。对话工具里加 `withInterpret: true` 即可一并返回。

- **结构化输出**：`{ moduleType, system, title, lead, dimensions[], sections[], disclaimer }`；`moduleType` 为 `natal`（命盘）/ `divination`（卦象）/ `card`（牌阵），`dimensions` 固定五个维度；`sections` 可带 `tone`（`good`/`watch`/`bad`），面板据此上色
- **分层结构与逐宫（0.43 新增）**：紫微多出**命身底色**（命宫主星 + 亮度 + 双星组合 + 身宫落点）、**逐宫分析**（十二宫各一条：宫位取象 + 主星亮度 + 吉星/煞星 + 四化，下接一句读法）与**三层格局**（有利格局 / 结构提示 / 忌格提醒，每条写名称、人话、依据与做法）；八字多出**命局框架**（日主/用神/格局 + 一句命局基调）、**正面画像**（外在取象 / 性格底色 / 事业与家庭）、**流年时间轴**（近三年逐条给档位与理由）与**专业建议**（喜用落地 / 忌神自觉 / 地支关系 / 调候）。措辞取自两份独立词库 `engine/ziwei-words.js`、`engine/bazi-words.js`——引擎只出事实，词库只出说法，词库里没有任何判断条件
- **五个维度**：整体运势、工作与职业选择、事业发展、爱情与感情、健康状况——每项给「解读 + 行动建议」；紫微的维度只点名六煞（擎羊/陀罗/火星/铃星/地空/地劫），其余杂曜留在逐宫，避免满屏星名
- **依据可核对**：每个维度都附一行「依据」，列出这条结论引用的事实——命盘类（八字/紫微）给日主旺衰、月令、喜忌、大运流年、宫位主星与煞星；卦象类（六爻/梅花/六壬）给本卦互卦变卦、世应、动爻、三传四课与神将；塔罗给牌阵、主轴、正逆位与元素分布。面板与文本两条输出路径都会显示
- **报告化阅读**：解析区顶部有「一页读懂」（整体/事业/财富/感情/节奏五条摘要）、目录锚点，以及三张表——八字是「大运表 / 流年表 / 触发事件表」，紫微是「大限表 / 流年表 / 触发事件表」。表格只把已有字段摊平，不新增判断；打印时表格不撕页、目录自动隐藏；≤640px 时表头隐藏、一行摊成一张卡（每格用列名当行标），不再出现六列排到 748px、右半边被截断又看不出能横滑的情况
- **证据卡与置信度**：每个维度的依据收进可展开的 `<details>`，点开可见逐条盘面事实与所用技法；维度旁标注「置信度 强/中/弱」（按证据条数分档，不引新算法）。文本输出同样带「置信度：…」
- **看示例**：面板与独立页都有「看示例」按钮，用固定的示例盘（1990-05-12 14:30 男 石家庄）走与真实排盘相同的渲染路径
- **追问**：工具参数 `ask`、面板与独立页的追问输入框——围绕**已算好的盘**回答「2027 年事业怎么样」「财运如何」这类问题；只取盘面已有字段（流年/大运/宫位/分节），不重排、不猜测；年份超出已排范围或没识别到方面时，明确说找不到并给出可问范围
- **问进对话**：面板追问框旁边多一个「问进对话」按钮——把这张盘的白话结论、摘要和你的问题拼成一段提问，**直接写进 DSH 的对话输入框并提交**（走输入框正常的回车路径，有回合在跑时排队、不打断当前回答），由对话里的模型接着答；提问模板把面板已算好的「直答 / 说人话」放进「开场结论」小节，要求模型开场先沿用它再展开，并写明「不用重排盘、要引到具体柱/宫/爻、没依据就说看不出来、别给绝对化断言」，按「开头一句无术语结论 → 每条判断分**盘面｜白话｜倾向｜边界**四行 → 收尾一句『如果只记一件事』」的骨架答，术语出现一个就当场翻成日常话（调候 / 化气 / 通关 / 空亡 / 争合 单独点名）。插件的对话桥还没挂上时（例如插件刚装好还没重启）退回复制，提示你粘进对话窗
- **八字 × 紫微 交叉验证**：工具参数 `cross`（或面板勾选）会用同一份出生信息再排另一套盘，对事业/财富/感情/身体/节奏五项并列对照，标注「同向 / 有张力 / 互补」；只作对照，不把两套体系折算成同一个分数。面板与独立页把它画成**对照卡**：一个方面一张卡，标题行带判断标签（绿 / 琥珀 / 蓝），八字与紫微各占一栏，注释放最后一行；窄屏改单列——不再是五段「八字——…；紫微——…；判断：…」的长句连读（Markdown 与工具输出仍是原来的五行文本）
- **量化口径**：只量化引擎已有数据（十神权重、大运/流年档位、宫位与四化计数），**不换算金额、不给健康诊断**；报告里有「量化口径」分节写明这条边界
- **方法与验证**：独立页内置同页「方法与验证」（体系、128 条卦例与 20 个奇门时辰对拍、测试文件与断言条数取自断言基线、七道闸、口径与已知边界），离线可开
- **夏令时校正（0.18 新增）**：1986–1991 年中国夏令时期间的钟面时间在排盘前自动减 1 小时（跨日回退），八字/紫微/合盘/验前事/生时校正统一生效；出生证已是真实太阳口径时可用 `dst: false` 关闭
- **合婚明细层（0.18 新增）**：合盘新增属相六合/三合/六冲/相害/相刑、天干五合、双向十神、跨盘地支、年命纳音与吉凶象计数分档；只作明细，不改原总分
- **晚子时开关**：面板与独立页都能切「23:00 后算次日/当日」；奇门另可切「归当日/归次日」——这是排盘口径，不是结果重算
- **验前事**：八字报告下方列出过去 6 年流年信号，用户自评「准/不准/不确定」，算一个贴合度提示；只读、不改盘
- **生时校正**：输入过去 2–3 件大事（年份 + 类别），对候选时辰逐一排盘并按固定规则打分，返回候选排序——用于缩小时辰范围，不替代出生记录
- **导出**：面板与独立页都能「导出 .md」（盘面 + 一页读懂 + 三张表 + 交叉验证 + 追问）；独立页另有打印/存 PDF
- **推导可复核**：八字/紫微另有「看盘顺序」「时间窗」「交叉校验」「未纳入」四段——先看什么后看什么、未来几步大运与近五年流年、喜忌分量与运年是否同向、以及这套算法**没有**计算什么；六爻/六壬对应给「看卦/看课顺序」与「未纳入」。这些都从盘面数据推出，不新增断语
- **卦象**（六爻/梅花/大六壬）额外给：卦名与卦辞大意、爻辞与动爻、体用关系、互卦与变卦、落到生活里
- **塔罗**额外给：整盘连贯解读（把几张牌串成一条线，避免各张互相矛盾）与牌面结构（大阿卡纳占比、元素分布、正逆位）
- **文案口径**：第二人称、温和、只给倾向与建议，不作绝对判断；底部保留理性参考的免责提示
- **解读区可折叠**：内容较长（五维度 + 体系模块），点标题栏或箭头即可展开/收起；宽屏默认展开、窄屏默认收起，手动切过之后按你的选择来
- **窄屏与深色（0.48 新增）**：390×844 下实测并修过一轮——目录改成单行横滑胶囊（隐藏滚动条、首尾留 11px），目录链接、证据摘要、名词解释摘要统一 44px 触摸高度；表头从 `--label` 换成 `--ink2`（浅色 10.5:1、深色 10:1），卡内标签与备注用 `--muted`（5.3:1 / 6.7:1），三档判断标签与目录链接在两套变量下都 ≥4.5:1；全部只走主题变量，深色仍然只换变量。dsh 侧栏「窗口宽、报告窄」不触发 `@media`，同一批规则按 `.mp-it` 的容器宽度另挂一份 `@container`，420px 侧栏下同样摊成卡片

### 所问之事与询问方向（六爻 / 梅花 / 大六壬 / 塔罗）

问事的体系要先说清问什么，解读才有落点：

- **所问之事**：必填，支持多行，占位示例「用一句话描述所问之事，例如：今年是否适合换工作？」；不填就起卦会给提示，不会给一份没有落点的解读
- **询问方向**：下拉选择——综合（默认）、财运、事业、感情、健康、学业、出行。选项表 `DIRECTIONS` 由 `engine/interpret.js` 导出，界面与解析层共用一份，不两处维护
- **联动方式**：`interpret(result, { question, direction })`。所选方向对应的维度会被提到最前并标注「最贴近你的问题」，正文点明你所问的事，引语也会回显；解读开头固定一行「问题：xxx ｜ 询问方向：xxx」供你确认
- **不重摇卦**：改问题或方向只重出解读，卦象本身不动
- 命盘类（八字 / 紫微）不问事，不显示这两项，也不会出现回显行

## 使用

### 对话里

直接说：

- 「排个八字：1990-05-12 14:30，女，河北石家庄」
- 「排紫微盘：1990-05-12 14:30，女，河北石家庄」
- 「帮我起一卦，问这个项目能不能成」
- 「梅花易数，报两个数 17 和 29」
- 「起个六壬课，问这周谈判顺利吗」
- 「抽三张塔罗，问这份工作要不要接」

模型会调用 `metaphysics_chart` 工具，参数 `system` 取 `bazi` / `ziwei` / `liuyao` / `meihua` / `daliuren` / `tarot`。
注意：八字与紫微要**出生时间**；六爻、梅花、六壬只要**起卦时刻**（通常就是当下），与出生时间无关。

### 面板

重启后侧栏出现**太极图标**，点开是排盘面板：紫微 / 八字 / 六爻 / 梅花 / 六壬 / 奇门 / 合盘 / 塔罗八个排盘 tab，另有黄历 / 农历 / 择日 / 称骨 / 小六壬 / 星座 / 生命数字 / 人生K线 / 风水 / 起名 / 十六型人格十一个速查 tab。奇门 tab 里「换局规则」可选拆补、超神接气、置闰；盘面下方用键值表列出局数、值符值使、空亡驿马、击刑与入墓、月令与门星干旺衰、干宫生克等事实，与解读区的结论分开。

结果卡下方的追问行里，输入问题后可以点「追问」（在本地按盘面字段直接答，不联网）或「问进对话」（把提问发进 DSH 对话窗，由模型接着答）。

> 独立页（`命理排盘.html`）同样是这十九个 tab：速查 tab 在左侧展开对应小表单（择日的起算日/事项/天数/属相、农历的转换方向/农历日期/闰月、小六壬的时间或报数、风水的命卦/门主灶/玄空与坐向、运（结果都是方位网格：八向标吉凶、玄空九宫列运/山/向三数）、起名的评估或生成、十六型人格的分页问卷（4 题一页、1–5 打分，答满 12 题可先看结果））；合盘要填双方出生信息、可选八字/紫微两种合盘；奇门用「换局规则」单选组（拆补/超神接气/置闰）与「询问方向」定用神。这份文件与侧栏面板是**各自生成**的两份产物（同一份 `engine/`），随包发布的是仓库根这一份；自己在桌面另存过的话，用 `npm run build:desktop` 一次刷新两处，别手工拷。

> 首屏默认按用途分三组：**问一件事**（六爻/梅花/塔罗/奇门/六壬/小六壬）、**看一个人**（八字/紫微/合盘/人格/称骨/数字/人生K）、**查日子**（黄历/择日/农历/星座/风水/起名），每项带一句白话（如「摇六次，问一件事」）；用过的入口会进「最近用过」，最多 3 条。19 个平铺 tab 仍保留，右上角「分组 / 平铺」随时切换，选择记在本机；手机端每组先露 4 项，其余点「还有 N 个」展开。这份分组数据只有一份（`src/groups.mjs`），独立页与宿主侧栏面板在构建时各自取用；侧栏宽度不等同窗口宽度，收纳按容器查询生效。

### 深色与导出

- **深色主题**：跟随系统（`prefers-color-scheme`），盘面与页面同时切换，只换一套 CSS 变量，元素规则一行不改
- **打印永远是浅色**：深色主题下直接打印会得到一整页耗墨的深底 PDF，所以深色规则用 `@media screen` 限定
- **存为 PDF / 打印**：结果下方有按钮，走浏览器原生打印（不引第三方库）；A4 纵向、隐藏输入区与按钮、盘面与解读不被撕页、四化色块保留颜色。折叠着的「解析与详解」在打印时会自动展开，不会只印出一个标题栏

## 精度与口径

- **节气**：VSOP87B 截断级数（105 项）+ 岁差 + 章动 + 光行差；与日本国立天文台《暦要項》对拍，2024/2025 共 48 个节气最大偏差 **0.6 分钟**；出生时刻距「节」不足 20 分钟时会提示复核。**1929-01-01 之前按北京地方平时（UTC+7.7611）**推算，之后按东八区——与农历共用同一套换算，避免 14 分钟错位
- **农历**：定朔（Meeus 第 49 章，误差约 1 分钟）+ 冬至所在月为十一月 + 无中气置闰
- **真太阳时**：经度差 + 均时差；内置 34 个省会 + 200 个地级市坐标（±0.2°），地址更细时可开「联网精确到区县」（Nominatim）。**单盘与合盘用的是同一套修正**（合盘双方各按自己出生地算）。只按经度修正，**未含历史时区与夏令时**：海外出生请先把当地钟表时间换算成东八区标准时再输入；没给经度时摘要首行会出 ⚠
- **晚子时**：八字/大六壬默认 23:00 后换日，奇门默认归当日；`lateZi` 与 `lateZiHourMode` 是同一个开关的两个名字。各体系摘要都会写明本次采用的口径，不改默认值、不偷偷改盘
- **口径对照**：`caliberCompare` 只做「当前口径 → 另一档」的逐字段比对，根因按柱 / 命宫 / 局数 / 起运归类，`total` 是变化字段数、不是分数；没有根因时写明「无单一根因」（如真太阳时只改起运时刻）。紫微的 11 组含九类流派开关（亮度 / 庚干四化 / 天马 / 天空 / 截空旬空 / 魁钺 / 天伤天使 / 长生 / 晚子时），平铺参数与 `schools` 嵌套都能读；取局流派、晚子时归日、闰月政策与流派回显属于口径回显，不计入差异；「其他」是尚未归类的派生字段，不隐藏也不折算。对照会按开关数多排盘（工具里由 `diff: true` 显式开启）
- **八字五合**：干支关系只标「有合」，摘要写「戊癸合（化火待定）」；是否真化另看月令、化神与争合妒合，不在关系层直接断「合化火」
- **可复现**：塔罗/六爻给 `seed` 即得同一次抽牌/摇卦；紫微流月流日流时、塔罗的抽牌时刻、八字的流年基准年都可传 `asOf` 钉死。**影子盘** `shadow: true` 另给一个短 ID：同参数同 ID、换版本 `id` 变而 `baseId` 不变；面板与独立页把快照存在本地，同盘重排自动做字段级 diff。未固定 `asOf` 时流年随「此刻」变化，卡片会提示先固定再比对；与 `seed` 一样，随机源不写进 ID 时无法复算，所以塔罗 / 六爻的实际牌面会算入指纹。**推导链** `trace: true` 则逐层给出规则、输入、结果与出处，只读结果，不改变盘面与 ID
- **紫微四化**：中州派常用表（庚干作太阳禄、武曲权、太阴科、天同忌）
- **问进对话**：只做文本组装，不改盘、不调模型——面板把 `Engine.askPrompt` 生成的一段话交给 DSH 客户端槽位 `conversation.input.right` 拿到的 `inputActions`，先 `setDraft` 再 `submit`（官方输入框的正常提交路径）；桥不在时退回复制剪贴板并给出提示。提问里带的盘面摘要按 3000 字截断并标注「摘要已截断」；面板已有解析时，模板会在摘要之前插入「开场结论」小节（直答 + 说人话，原样取自面板结果），让对话开场与面板同一口径；固定骨架（抬头 + 回答要求）约 520 字，不随 `maxChars` 变，`test/ask-prompt.test.mjs` 有断言盯它别长成小作文。这条链依赖 Harness 的客户端 slot API（`conversation.input.right` + `inputActions`），升级 Harness 后若槽位改名，按钮会静默退回「复制」而不是报错
- **紫微飞星串连**：只认宫干四化表、星落哪宫就是哪宫之力，串连只跟**同一支化**逐宫跳（不混支、不借对宫），满 12 步或回到走过的宫即停；宫干四化在 12 宫上是「一个宫 → 一个宫」的函数映射，所以完整盘上每条链必然成环（实测 1/3/4/5/6 步），「断点」只可能来自星未上盘。这一层只描方向与牵引，不断吉凶，也不叠大限流年算力重
- **八字 × 紫微交叉验证**：五项只并列、不合并成总分。任一侧当前阶段取不到时（八字尚未起运、紫微大限不在范围内），该项标「互补」并写明缺的是哪一边，不把「没取到」当成「没有问题」；节奏一项的说明按实情分档——八字顺而紫微煞星多、八字偏紧而紫微平静、八字为平而紫微煞星多，三种说法各写各的，不共用一句「一边顺、一边压」
- **日主旺衰**：量化算法，非唯一流派
- **奇门宫位条件**：门迫只认同宫内「门五行克宫五行」，宫克门是「宫制门」不为迫；六仪击刑按月支相刑定宫（甲子戊震三、甲戌己坤二、甲申庚艮八、甲午辛离九、甲辰壬巽四、甲寅癸巽四），三奇入墓按五行墓库定宫（乙木墓未→坤二、丙丁火墓戌→乾六）。这三项只判**天盘**、只作宫位条件，不自动断用神受制，也不打分排序
- **奇门旺衰**：八门、九星与天盘干（三奇六仪）按月支五行判旺相休囚死（同气旺、月令所生相、生月令休、克月令囚、被月令克死），只报力量强弱不折吉凶；门旺而宫克门仍受宫制。
- **六爻用神旺衰**：月建按月支五行定五态（同气旺、月令所生相、生月令休、克月令囚、被月令克死），日辰定五关系（日生/日克/比和/泄/耗），月建冲爻标月破、日辰冲静爻标暗动、冲旬空标冲空；只报状态标签，不折成分数
- **六爻全卦逐爻旺衰**：与用神旺衰同一套判定，只是不挑用神、六爻全给，并标世应/动爻/旬空与五态分布。五态只按「爻五行 × 月支五行」判，各家对月破、暗动、冲空取名不一，本插件按「月建冲=月破、日冲静爻=暗动、日冲旬空=冲空」给标签；不折加权分数、不据此断成败；化进/化退已叠月建五态给档位（见下一条），但日辰加权与动变连环仍未做
- **紫微三方四正复合飞化**：四宫 16 条飞化按落宫归堆，会聚判定只看「落在同一宫」这一条结构事实（双忌≥2、禄忌同见、三化以上、自化）；各家对会照要不要折分数、要不要再叠大限流年分歧较大，本插件只标会照与方向
- **紫微夹局与刑囚夹印**：「夹」只要求两星分居命宫前后、不分左右（日月、左右、魁钺本来就没有固定左右；0.38.2 之前按固定顺序判，昌曲夹命与羊陀夹命从未命中，日月/左右/魁钺各漏约一半）。擎羊在禄存 +1、陀罗在禄存 −1，两星只能夹禄存，所以「羊陀夹命」即禄存守命、「羊陀夹忌」即化忌与禄存同宫。刑囚夹印按字面判夹不成立（廉贞与天相永远隔偶数宫），取通行说法「廉贞天相同守命宫于子午、擎羊同宫」，判的是守命那一宫，其它宫位三星同宫不报；命宫卯酉、廉贞天相对照遇擎羊的变体未纳入。34 条格局的判定与 `test/ziwei-patterns.test.mjs` 的独立谓词逐条对齐，并要求每条至少命中一次
- **奇门干宫生克**：天盘干（三奇六仪）与所落宫五行的关系另算一层——干克宫/宫克干/干生宫/宫生干/比和，与门宫关系并列各说各的、不折成一个分数；十干克应（天盘干加地盘干的 100 组）仍未做
- **六爻化进化退**：只按「同五行地支顺次」定方向（木 寅→卯、火 巳→午、金 申→酉、水 亥→子，土 丑→辰→未→戌→丑 成环），同五行不相邻不算；方向之外再按月建五态给一档力重（旺相 → 后劲足、休囚 → 后劲有限、死 → 进得虚；退则得令退得缓、失令退得实；月破压过一切），只给档位、不折加权分数，也不据此断吉凶。土的进退次序各家说法不完全一致
- **六爻应期线索**：只做「时间窗口的方向」——用神（不上卦取伏神）的逢值、逢冲、逢合三支，旬空另加出空填实与冲空；快慢按月建五态分偏速 / 偏缓 / 待解 / 未定（两现而旺衰不一或缺月建记未定）。不换算日期、不排先后、不判忌神受制，也不叠动变连环；近事以日计、远事以月计，用哪把尺由事情远近决定，本插件不代选。具体应期日期仍是 `liuyao-yingqi-exact` 的待办项
- **八字交运日**：交运时刻 = 出生时刻 + 「出生到起运侧节令」的真实天数 × 365.2422/3，顺排数到下一节、逆排数到上一节；同一条比例即古法「三日折一年、一日折四月、一时辰折十日」。每步大运在同月同日同时刻换，闰日退位。一年取回归年 365.2422 日——按 360 日折算的流派会差一两天，`dayun.jiao.yearDays` 把这个口径写进了结果
- **八字通关**：只在「用神与克它的忌神两行在局中各 ≥1.5 分」时成立相战，通关行由五行生克唯一确定（克方所生、又生用神；金克木以水为关），按局中分量分「可通 / 关弱 / 为忌 / 未通」四档，`usable` 仅指「可通」；通关行若在本盘属忌神，只标「为忌」、不当桥用。只写进用神 detail、摘要与解释层，不折分数、不断吉凶，也不判通关之力够不够用。`test/tongguan.test.mjs` 用五组相克、阈值边界与 24 年逐月真实盘独立重算核对
- **岁运提示**：六类信号只认干支事实——**天克地冲**要求天干相克且地支相冲，缺一不算（例如丙子年对丙午年柱是同干相冲，不标反吟）；当值大运取与「该年立春到次年立春」相交的步，交运落在年内时前后两步并列。不折分数、不判吉凶，「岁运并临主大凶」一说不采；大运与本命四柱的伏吟/反吟整步大运都在，随每年重复列出、不逐年加重；四柱十神的引化也未叠入
- **六爻用神**：只落到「哪一爻是用神、它与卦体/动变/旬空什么关系、月建日辰给它什么状态」这一层——不叠出一个月建日辰换算的力重分数，用神两现时把候选都列出来而不代选；伏神给出伏于何爻、飞伏生克与出伏条件（飞生伏、伏克飞、日辰生/比和、月建旺/相算助，飞克伏、日辰克、月破算压，归四档），条件只并列、不排各家优先级，也不出具体日期与应期
- **十六型人格**：MBTI **风格**的自建问卷，不是官方 MBTI 量表——题目、计分与常模都是本插件自己的，不与任何商业量表对齐；四维净分 =（分数 − 3）× 侧向求和，平手按 I / N / F / P 取并标「临界」，强度是按「净分 / (答数 × 2)」分的四档，不代表任何总体分布。结果只作自我参照，不用来评价他人能力、做招聘或临床判断
- **入参**：日期按月份天数与闰年校验（`1990-02-30` 直接报错，不滚到下个月）；八字/紫微/合盘的性别必填（性别决定大运大限顺逆，不做默认）；六爻爻值必须正好 6 个，留空才随机摇卦。非法入参带错误码返回（`E_INPUT` / `E_LINES` / `E_COUNT` / `E_ASOF` / `E_PARTNER`），不静默改成另一个盘；风水缺坐向、非 24 山、坐向不对宫、运越界与运非整数（含字符串）同样归 `E_INPUT`，工具层不会把它们标成内部错误，也不会把 `2.5` 静默当成缺省九运
- **对拍**：历法对 NAOJ 历要项与 ICU 抽样的农历；流派规则对典籍通例——六爻八宫卦序与世应（京房）、六壬日干寄宫与中气换将（《大六壬指南》）、紫微纳音定五行局与紫微天府相照（《紫微斗数全书》）；另有《增删卜易》9 条与《卜筮正宗》**128 条**原文卦例（93 条本卦→变卦 + 35 条静卦）。期望值在 `test/fixtures/classics.json`，出处见其 `meta.sources`，卦例原始数据与排除理由在 `tools/data-boshizhengzong.mjs`。卦例只取原文能稳定读出的字段：卦名、卦宫、缺爻（伏神）、动爻**个数**（与原文 x/○ 标记数核对过）、有日期的旬空；**动爻在哪一爻**不录——卦象表在 PDF/DOCX 里串行，硬解析等于造数据

## 开发

```bash
npm run build        # 生成 client.js（界面入口）与 client.<name>.js（按 tab 的引擎分块）
npm run build:html   # 生成独立的 命理排盘.html（可离线双击使用），默认写到工作区根目录

# 想同时更新桌面那份：npm run build:desktop（写到 ~/Desktop/命理排盘.html）
# 存到别处：node tools/build-html.mjs --out "D:\某处\命理排盘.html"
npm test             # 顺序跑完 test/ 下全部 *.test.mjs 并汇总
npm run test:ci      # 构建 + 产物自检 + 回归 + 断言基线 + 测试自检 + HTML 注入面 + 工程约定（CI 跑的就是这条）
npm run test:baseline # 断言数确实要减少时，显式重建基线
npm run check:html   # 单独跑 HTML 注入面扫描
npm run check:patterns # 单独跑工程约定检查
npm run release      # 测试 → 构建 → 校验产物 → 发 npm → 核对附件（token 从 NPM_TOKEN 读）
```

也可以直接调脚本：`node tools/build-client.mjs`、`node tools/build-html.mjs`、`node tools/verification.mjs`、`node tools/caliber-diff.mjs`（同盘换口径的逐字段对照）、`node tools/check-bundle.mjs`、`node tools/test-all.mjs`、`node tools/check-assertions.mjs`、`node tools/verify-tests-can-fail.mjs`、`node tools/check-html-sinks.mjs`、`node tools/check-patterns.mjs`、`node tools/release.mjs`、`node tools/verify-publish.mjs`（被 release 调用，也可单独用来核对某个版本）。

**测试的七道闸**：

1. `test/_harness.mjs`——任何一条 `ok()` 失败都让进程非零退出（此前 9 个文件只打印不失败，全量"全绿"没有意义）
2. `test/assertion-baseline.json`——每个文件的 PASS 条数低于基线即失败，防止"删断言让测试变绿"
3. `tools/verify-tests-can-fail.mjs`——故意写错一条断言，必须真的变红，防止第 1 条被改回去
4. `tools/check-html-sinks.mjs`——`innerHTML` 里拼接的量必须经过白名单转义函数，否则 CI 直接红
5. `tools/check-patterns.mjs`——engine 不得引用浏览器/Node API 与 `console`，不得用 `var`/`debugger`，`new Date()` 与 `Math.random` 只允许出现在白名单文件
6. `test/fuzz.test.mjs`——固定种子的随机生日扫射八个排盘体系，覆盖边界日期、参数矩阵与"同参数必得同结果"
7. `tools/check-bundle.mjs`——产物必须在**宿主形态**下能编译能跑：读 `client.js` 与每个 `client.<name>.js` 原文逐模块编译、模拟 `__ModuleLoader__` 执行 factory、校验分块注册名 / 返回 `Engine` / 自包含、IIFE 收口与不可见分隔符，并要求所有产物与源码重构建逐字节一致；入口 gzip 必须 < 100KB（2026-10-25 的启动崩溃就是 Node 侧全绿、Chromium 侧语法错，这道闸专门守这个缝）

`client.js` 与 `client.<name>.js` 都是构建产物，不要手改。入口只带界面；面板按当前 tab 用 `require.async` 取引擎分块，首次打开不再下载整套引擎。改动记录见 [CHANGELOG.md](CHANGELOG.md)。

### 发版

```bash
# 先在 npm 生成 Granular Token：Read and write + 勾 Bypass 2FA
NPM_TOKEN=npm_xxx npm run release              # 正式发布（会先跑测试与构建校验）
NPM_TOKEN=npm_xxx npm run release -- --dry-run # 只校验不发布
NPM_CLI=/path/to/npm-cli.js NPM_TOKEN=... npm run release   # 本机没有 npm CLI 时
node tools/release.mjs --verify-only           # 只核对 registry 上当前版本的附件
```

脚本会拦下：工作区不干净、`client.js` 未随源码重建、registry 上已有同版本；发布后自动核对新版本与 `dist-tags`，并提示补 `git tag`。

**发布后为什么要看附件，而不是只看 `npm publish` 的输出**：npm 的发布是异步的，版本条目会先出现在 packument 里（连 shasum、签名、`latest` 都齐），tarball 附件却可能晚几分钟才落盘。这中间别人 `npm i` 会撞 404，而 `npm publish` 早就打印了成功。所以 `tools/verify-publish.mjs` 的判据是四条：tarball 返回 200、下载到的字节 sha1 与 registry 记的 `shasum` 一致、`fileCount` 对得上、包里该有的文件（`package.json`/`client.js`/`命理排盘.html`）确实在。15 分钟内一直对不上就判定失败并给出处置路径。

另外记一条实操限制：`unpublish`/`deprecate` 属于「绕过 2FA 的破坏性动作」，granular token 会被 403 拒绝（`Granular access tokens that bypass two-factor authentication may not perform this action`），这类动作只能在 npm 网页上用 2FA 做；真要撤版，把版本号升一个补丁号重发通常更快。

### 样式命名约定

面板的 CSS 是以 `<style>` 注入到宿主页面的，**没有 shadow DOM 隔离**，所以每个类名都带命名空间前缀，避免和宿主页面的同名元素互相染色：

| 前缀 | 归属 |
|---|---|

两条硬规矩：

- **不用泛词做类名**（`.body`、`.big`、`.s`、`.p`、`.on`、`.it` 这类）。名字越泛，越容易在同一个文件里被两处语义共用——本项目已经栽过两次：`.pp-body` 同时是「整块视图容器」和「身宫格」，一次导致身宫整格消失，另一次的 `::after` 残骸在页面左上角飘出一个孤立的「身」方块。
- **模块根类名必须带前缀**。裸用的 `.it` / `.dl` / `.hy` 一旦注入全局，宿主页面的同名元素会被一起改写。
