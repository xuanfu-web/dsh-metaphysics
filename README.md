### 报告化与可核验（0.16 / 0.17 / 0.18 / 0.20 新增）

- **一页读懂 + 三张表**：整体/事业/财富/感情/节奏五条摘要；大运表、流年表、触发事件表（紫微是大限/流年/触发）
- **证据卡 + 置信度**：每条维度结论可展开到逐条盘面事实与所用技法，置信度按证据条数分强/中/弱
- **追问**：工具参数 `ask`，围绕已算好的盘回答「2027 年事业怎么样」这类问题；不重排、不猜测，找不到会明说
- **排盘句柄**：每次结果带 `handle`（形如 `mc1.…`），下一次只传 `{ handle, asOf, direction, question }` 这类增量就能追问同一张盘，或传 `{ handle, system: 'ziwei' }` 看同一时刻另一套盘，不必重报出生时间与出生地。句柄把参数编码进去（不依赖进程内存），键序固定、带校验位，截断或改字报 `E_HANDLE`；`trace` / `shadow` / `withInterpret` 这类输出开关不进句柄。它是编码不是加密——含出生时间与出生地，别公开贴出。随机抽牌只复现参数、不复现牌面，要复现须带 `seed`
- **一句话改参**：工具参数 `revise`（可配合 `handle`）接住「换成紫微看 2030 年事业」「女命」「晚子时算次日」「出生在成都」「不用真太阳时」「详细解读一下」这类原话，引擎翻成参数补丁再排盘，并在结果 `revision` 里回报改了哪些、没认哪些。只认明确句式——换体系要有切换词，单提一句「紫微里怎么说」不换盘；出生年份与时辰一句话给不出分秒，不猜，改为提示直传 `datetime`。识别不到时盘面一字不动。摘要给「【改参】原话 + 旧 → 新 + 未处理」，面板与独立页给改参卡

### 所问之事与询问方向（六爻 / 梅花 / 大六壬 / 塔罗）

问事的体系要先说清问什么，解读才有落点：

- **所问之事**：必填，支持多行，占位示例「用一句话描述所问之事，例如：今年是否适合换工作？」；不填就起卦会给提示，不会给一份没有落点的解读
- **询问方向**：下拉选择——综合（默认）、财运、事业、感情、健康、学业、出行。选项表 `DIRECTIONS` 由 `engine/interpret.js` 导出，界面与解析层共用一份，不两处维护
- **联动方式**：`interpret(result, { question, direction })`。所选方向对应的维度会被提到最前并标注「最贴近你的问题」，正文点明你所问的事，引语也会回显；解读开头固定一行「问题：xxx ｜ 询问方向：xxx」供你确认
- **不重摇卦**：改问题或方向只重出解读，卦象本身不动
- 命盘类（八字 / 紫微）不问事，不显示这两项，也不会出现回显行

## 使用

### 对话里

直接说：

- 「排个八字：1990-05-12 14:30，女，河北石家庄」
- 「排紫微盘：1990-05-12 14:30，女，河北石家庄」
- 「帮我起一卦，问这个项目能不能成」
- 「梅花易数，报两个数 17 和 29」
- 「起个六壬课，问这周谈判顺利吗」
- 「抽三张塔罗，问这份工作要不要接」

模型会调用 `metaphysics_chart` 工具，参数 `system` 取 `bazi` / `ziwei` / `liuyao` / `meihua` / `daliuren` / `tarot`。
注意：八字与紫微要**出生时间**；六爻、梅花、六壬只要**起卦时刻**（通常就是当下），与出生时间无关。

### 面板

## 读之前：象与数

这套东西分三层——**数**（可复算的坐标：干支、节气、纳甲、十神、宫位）、**象**（坐标之间的关系：当位、承乘、合冲、伏墓）、**辞**（一句判断：吉凶、应期）。普通人读原文读不下去，多半是从「辞」开始背，跳过了前两层。

问事体系（六爻 / 梅花 / 六壬 / 奇门 / 塔罗 / 小六壬）另有一套固定流程：**先确认问的是哪件事 → 找到代表「我」和「事」的符号并说明为什么是它 → 看落位与关系 → 回到现实核对**，开口前还要能过三追问。命令行一句 `npm run prompt:event -- --system liuyao --kind career --question "…"` 就能拿到填好盘面的完整提示，规则与各体系的取用神表见 `docs/问事解读提示.md`。

`docs/象与数-要义导读.md` 是把这三层讲成人话的一篇长文：数是坐标系、象是关系、辞是名字；纳甲为什么必须存在、十神与宫位各自站在哪、为什么「同一个用神伏藏」能读出相反的结论、以及**怎么用三个问题判断一句断语是不是在裸奔**。不教断命，只帮你把事情分清楚：哪些算得准、哪些可商量、哪些只能自己决定。

## 先说结论

排完盘，**最上方**是一段人话总结（方框）：这张盘／这一卦大致在说什么、关键落点在哪、最容易卡住的地方，再加几条可以立刻做的事。它在盘面之前——先给结论，再用下面的盘面作依据；反过来大多数人读不到第二屏。

九个体系都有这一屏：八字（底色／感情／卡点）、紫微（命身／夫妻宫／被冲破的格局）、六爻（世爻／用神／成不成看哪里）、梅花（体用与过程结果）、六壬（起手—转折—落点）、奇门（你的宫与事的宫、门星神）、塔罗（逐张位置义）、合盘（日主关系／夫妻宫／五行互补）、人生 K 线（这一步的基调、最亮与最闷、怎么用）。

其中两条是特意做的「不许糊弄」：六爻若「询问方向」还停在综合，取不到用神，它不会硬给一个结论，而是改读世应与卦体，并把「为什么没有结论、该补哪一步」写在方框里；走势若没拿到当前日期（`asOf`），它不猜「你现在几岁」，直接说明不标当前位置。

这段只做「结构 → 人话」的翻译，不下吉凶断语：可以写「你容易遇到两种类型的人」，不会写「你婚姻不好」。同一张盘每次生成的文字完全一致（引擎不读挂钟，当前时间由界面传入）；时辰未知时它会先说明「只据六字、约七成信息」。

## 精度与口径

- **节气**：VSOP87B 截断级数（105 项）+ 岁差 + 章动 + 光行差；与日本国立天文台《暦要項》对拍，2024/2025 共 48 个节气最大偏差 **0.6 分钟**；出生时刻距「节」不足 20 分钟时会提示复核。**1929-01-01 之前按北京地方平时（UTC+7.7611）**推算，之后按东八区——与农历共用同一套换算，避免 14 分钟错位
- **农历**：定朔（Meeus 第 49 章，误差约 1 分钟）+ 冬至所在月为十一月 + 无中气置闰
- **真太阳时**：经度差 + 均时差；内置 34 个省会 + 200 个地级市坐标（±0.2°），地址更细时可开「联网精确到区县」（Nominatim）。**单盘与合盘用的是同一套修正**（合盘双方各按自己出生地算）。只按经度修正，**未含历史时区与夏令时**：海外出生请先把当地钟表时间换算成东八区标准时再输入；没给经度时摘要首行会出 ⚠
- **时辰未知**：不知道出生时刻时勾「时辰未知」，八字只排年/月/日三柱，时柱不给、命宫身宫不排、起运与交运降到按日（`dayun.precision: 'day'`），摘要第一行固定写「时柱按正午暂算，涉及时柱的结论仅供参考」；工具侧传 `hourUnknown: true` 等价（八字 / 趋势可用）。**紫微与合盘会直接报 `HOUR_UNKNOWN`**：这两套离开生时支就不成立，硬排出来只是看着像盘。全文不出现 `12:00` 这类占位钟点。
- **晚子时**：八字/大六壬默认 23:00 后换日，奇门默认归当日；`lateZi` 与 `lateZiHourMode` 是同一个开关的两个名字。各体系摘要都会写明本次采用的口径，不改默认值、不偷偷改盘
- **口径对照**：`caliberCompare` 只做「当前口径 → 另一档」的逐字段比对，根因按柱 / 命宫 / 局数 / 起运归类，`total` 是变化字段数、不是分数；没有根因时写明「无单一根因」（如真太阳时只改起运时刻）。紫微的 13 组含十一类流派开关（亮度 / 庚干四化 / 天马 / 天空 / 截空旬空 / 魁钺 / 天伤天使 / 长生 / 晚子时 / 身主 / 杂曜全表），平铺参数与 `schools` 嵌套都能读；取局流派、晚子时归日、闰月政策与流派回显属于口径回显，不计入差异；「其他」是尚未归类的派生字段，不隐藏也不折算。每行另给 `views`：八字（日柱 / 时柱 / 旺衰 / 格局 / 喜用 / 起运）、紫微（命宫 / 身宫支 / 五行局 / 身主 / 起大限）、奇门（日柱 / 局数 / 值符 / 值使）的两列并排，只列变化项，摘要里写成「并排：日柱 丙辰 → 乙卯」，面板与独立页画成表格。对照会按开关数多排盘（工具里由 `diff: true` 显式开启）
- **八字五合**：干支关系只标「有合」，摘要写「戊癸合（化火待定）」；是否真化另看月令、化神与争合妒合，不在关系层直接断「合化火」
- **可复现**：塔罗/六爻给 `seed` 即得同一次抽牌/摇卦（不给 `seed` 时走系统加密随机源 `crypto.getRandomValues`，不是可被倒推的 `Math.random`——摇卦这件事本身要经得起「这次真是随机摇的」这句话）；紫微流月流日流时、塔罗的抽牌时刻、八字的流年基准年都可传 `asOf` 钉死。**影子盘** `shadow: true` 另给一个短 ID：同参数同 ID、换版本 `id` 变而 `baseId` 不变；面板与独立页把快照存在本地，同盘重排自动做字段级 diff。未固定 `asOf` 时流年随「此刻」变化，卡片会提示先固定再比对；与 `seed` 一样，随机源不写进 ID 时无法复算，所以塔罗 / 六爻的实际牌面会算入指纹。**推导链** `trace: true` 则逐层给出规则、输入、结果与出处，只读结果，不改变盘面与 ID
- **紫微四化**：中州派常用表（庚干作太阳禄、武曲权、太阴科、天同忌）
- **问进对话**：只做文本组装，不改盘、不调模型——面板把 `Engine.askPrompt` 生成的一段话交给 DSH 客户端槽位 `conversation.input.right` 拿到的 `inputActions`，先 `setDraft` 再 `submit`（官方输入框的正常提交路径）；桥不在时退回复制剪贴板并给出提示。提问里带的盘面摘要按 3000 字截断并标注「摘要已截断」；摘要之前先给「盘面层次」（按体系列 4–6 层阅读顺序，未知体系走通用兜底），再给摘要与回答骨架，让模型先复述事实、再讲结构与时间；面板已有解析时，模板在摘要之前插入「开场结论」小节（直答 + 说人话，原样取自面板结果），让对话开场与面板同一口径；六爻 / 梅花另在盘面摘要之后追加一节**《周易》经文原文**（本卦卦辞、动爻爻辞、互卦与变卦卦辞照录，取自 `engine/yijing-text.js`——模板只读结果里已算好的 `jing`，本身不引原文库，非卦象体系不多塞一段），别家模型拿到的不只是白话大意；固定骨架（抬头 + 层次 + 回答要求）约 700 字，不随 `maxChars` 变，`test/ask-prompt.test.mjs` 有断言盯它别长成小作文。这条链依赖 Harness 的客户端 slot API（`conversation.input.right` + `inputActions`），升级 Harness 后若槽位改名，按钮会静默退回「复制」而不是报错
- **紫微飞星串连**：只认宫干四化表、星落哪宫就是哪宫之力，串连只跟**同一支化**逐宫跳（不混支、不借对宫），满 12 步或回到走过的宫即停；宫干四化在 12 宫上是「一个宫 → 一个宫」的函数映射，所以完整盘上每条链必然成环（实测 1/3/4/5/6 步），「断点」只可能来自星未上盘。这一层只描方向与牵引，不断吉凶，也不叠大限流年算力重

- **奇门十干克应**：天盘干加地盘干按通行 100 组表逐宫取格名与取象（甲加丙「青龙返首」、庚加丙「太白入荧」、癸加癸「天网四张」等），与门宫、干宫生克并列，只作读盘线索，不自动折吉凶；底本取通行表，《奇门遁甲元灵经》卷二只存甲、乙、丙三组且文字有异，两本并列不合并
- **奇门干宫生克**：天盘干（三奇六仪）与所落宫五行的关系另算一层——干克宫/宫克干/干生宫/宫生干/比和，与门宫关系并列各说各的、不折成一个分数；它与十干克应（天地盘两干）是两层，互不替代
- **六爻化进化退**：只按「同五行地支顺次」定方向（木 寅→卯、火 巳→午、金 申→酉、水 亥→子，土 丑→辰→未→戌→丑 成环），同五行不相邻不算；方向之外再按月建五态给一档力重（旺相 → 后劲足、休囚 → 后劲有限、死 → 进得虚；退则得令退得缓、失令退得实；月破压过一切），只给档位、不折加权分数，也不据此断吉凶。土的进退次序各家说法不完全一致
- **六爻应期线索**：只做「时间窗口的方向」——用神（不上卦取伏神）的逢值、逢冲、逢合三支，旬空另加出空填实与冲空；快慢按月建五态分偏速 / 偏缓 / 待解 / 未定（两现而旺衰不一或缺月建记未定）。不换算日期、不排先后、不判忌神受制，也不叠动变连环；近事以日计、远事以月计，用哪把尺由事情远近决定，本插件不代选。具体应期日期仍是 `liuyao-yingqi-exact` 的待办项
- **知识标签只讲文本，不讲效度**：知识卡上那三个标签写全了是「文本·诸家一致 / 文本·各家有异说 / 文本·未录入」，意思分别是「各书都这么写」「各书写法不同」「我们还没录」，都不表示该技法有效。0.59.0 之前写作「诸家一致」，容易被读成「这说法可靠」，是产品在无意中误导。文末「这套规则有多稳」现在先列**本盘踩到的**分歧，再列本体系其余通行分歧——用户先要知道「我这盘有几处是取派分歧」，体系总账次要。`test/interpret-knowledge.test.mjs` 用断言锁住「标签必须带文本前缀」，防止被改回去
- **八字交运日**：交运时刻 = 出生时刻 + 「出生到起运侧节令」的真实天数 × 365.2422/3，顺排数到下一节、逆排数到上一节；同一条比例即古法「三日折一年、一日折四月、一时辰折十日」。每步大运在同月同日同时刻换，闰日退位。一年取回归年 365.2422 日——按 360 日折算的流派会差一两天，`dayun.jiao.yearDays` 把这个口径写进了结果
- **八字通关**：只在「用神与克它的忌神两行在局中各 ≥1.5 分」时成立相战，通关行由五行生克唯一确定（克方所生、又生用神；金克木以水为关），按局中分量分「可通 / 关弱 / 为忌 / 未通」四档，`usable` 仅指「可通」；通关行若在本盘属忌神，只标「为忌」、不当桥用。只写进用神 detail、摘要与解释层，不折分数、不断吉凶，也不判通关之力够不够用。`test/tongguan.test.mjs` 用五组相克、阈值边界与 24 年逐月真实盘独立重算核对
- **岁运提示**：六类信号只认干支事实——**天克地冲**要求天干相克且地支相冲，缺一不算（例如丙子年对丙午年柱是同干相冲，不标反吟）；当值大运取与「该年立春到次年立春」相交的步，交运落在年内时前后两步并列。不折分数、不判吉凶，「岁运并临主大凶」一说不采；大运与本命四柱的伏吟/反吟整步大运都在，随每年重复列出、不逐年加重；四柱十神的引化也未叠入
- **六爻用神**：只落到「哪一爻是用神、它与卦体/动变/旬空什么关系、月建日辰给它什么状态」这一层——不叠出一个月建日辰换算的力重分数，用神两现时把候选都列出来而不代选；伏神给出伏于何爻、飞伏生克与出伏条件（飞生伏、伏克飞、日辰生/比和、月建旺/相算助，飞克伏、日辰克、月破算压，归四档），条件只并列、不排各家优先级，也不出具体日期与应期
- **十六型人格**：MBTI **风格**的自建问卷，不是官方 MBTI 量表——题目、计分与常模都是本插件自己的，不与任何商业量表对齐；四维净分 =（分数 − 3）× 侧向求和，平手按 I / N / F / P 取并标「临界」，强度是按「净分 / (答数 × 2)」分的四档，不代表任何总体分布。结果只作自我参照，不用来评价他人能力、做招聘或临床判断
- **入参**：日期按月份天数与闰年校验（`1990-02-30` 直接报错，不滚到下个月）；八字/紫微/合盘的性别必填（性别决定大运大限顺逆，不做默认）；六爻爻值必须正好 6 个，留空才随机摇卦。非法入参带错误码返回（`E_INPUT` / `E_LINES` / `E_COUNT` / `E_ASOF` / `E_PARTNER`），不静默改成另一个盘；风水缺坐向、非 24 山、坐向不对宫、运越界与运非整数（含字符串）、兼向度数越界或坐向不一致、飞星日期/时刻格式非法同样归 `E_INPUT`，工具层不会把它们标成内部错误，也不会把 `2.5` 静默当成缺省九运
- **对拍**：历法对 NAOJ 历要项与 ICU 抽样的农历；流派规则对典籍通例——六爻八宫卦序与世应（京房）、六壬日干寄宫与中气换将（《大六壬指南》）、紫微纳音定五行局与紫微天府相照（《紫微斗数全书》）；另有《增删卜易》9 条与《卜筮正宗》**128 条**原文卦例（93 条本卦→变卦 + 35 条静卦）。期望值在 `test/fixtures/classics.json`，出处见其 `meta.sources`，卦例原始数据与排除理由在 `tools/data-boshizhengzong.mjs`。卦例只取原文能稳定读出的字段：卦名、卦宫、缺爻（伏神）、动爻**个数**（与原文 x/○ 标记数核对过）、有日期的旬空；**动爻在哪一爻**不录——卦象表在 PDF/DOCX 里串行，硬解析等于造数据

## 能力边界

这不是免责声明，是**具体的「不做什么」**。每条都对应引擎里的一处实现状况——改实现时同步改 `engine/limits.js`，`test/limits.test.mjs` 会核对清单与实现是否矛盾（例如写着「应期不给公历日期」，输出里就真不能出现日期）。

**所有体系共用三条**

- **技法效度未经检验**：能被复核的只有形式层（纳甲、干支关系、十神、宫位这类可由程序重算的部分），错了能查。解释层是各派通行说法，本插件不声称它比别的说法更准，也没做过能被别人重复的验证。
- **同盘不同命**：同一张盘对应无数人，从盘面推不出具体某一个人。这是模型的硬缺陷，不是样本不够——换更大的样本也补不上。
- **不给医疗、法律、投资建议**：不做疾病诊断，不判诉讼胜负，不做买卖与借贷决策。

**按体系**

- **六爻**：应期只给地支与快慢档，不折算公历日期——应期可取逢值／逢冲／逢合／出空／填实多种，折算成日期只是把不确定性藏进一个具体数字。回测 15 条规则命中 51.7%，平均要给 3.55 个候选支（随机基线 29.6%），高于随机但撑不起一个日期。用神两现时不代选。
- **八字**：不预测具体年份的事件（不判「哪年结婚／升职／发财」）。岁运并临、运年反吟、伏吟这类只作变动提示、不断吉凶——它们在十年里反复出现，按它们断事等于每年都能找到一次「应验」。旺衰是分档不是评分。化气格的真化判定仍缺实盘对拍。
- **紫微**：飞星层只报路径不判吉凶（串连与复合飞化的力重未定）；格局只判成立，破格条件未做。
- **梅花**：不取外应——外应的解释空间几乎没有边界，纳入后任何结论都能凑出来。
- **大六壬**：三课四传只给结构，应期推演未做。
- **奇门**：八门、九星入墓未做；用神落宫与击刑入墓只并列条件、不推结论。
- **塔罗**：只给通行牌义，不做联想式延伸。

面板每份报告底部有「本插件不回答什么」可展开，内容与上表同源。

**测试的七道闸**：

1. `test/_harness.mjs`——任何一条 `ok()` 失败都让进程非零退出（此前 9 个文件只打印不失败，全量"全绿"没有意义）
2. `test/assertion-baseline.json`——每个文件的 PASS 条数低于基线即失败，防止"删断言让测试变绿"
3. `tools/verify-tests-can-fail.mjs`——故意写错一条断言，必须真的变红，防止第 1 条被改回去
4. `tools/check-html-sinks.mjs`——`innerHTML` 里拼接的量必须经过白名单转义函数，否则 CI 直接红
5. `tools/check-patterns.mjs`——engine 不得引用浏览器/Node API 与 `console`，不得用 `var`/`debugger`，`new Date()` 与 `Math.random` 只允许出现在白名单文件
6. `test/fuzz.test.mjs`——固定种子的随机生日扫射八个排盘体系，覆盖边界日期、参数矩阵与"同参数必得同结果"
7. `tools/check-bundle.mjs`——产物必须在**宿主形态**下能编译能跑：读 `client.js` 与每个 `client.<name>.js` 原文逐模块编译、模拟 `__ModuleLoader__` 执行 factory、校验分块注册名 / 返回 `Engine` / 自包含、IIFE 收口与不可见分隔符，并要求所有产物与源码重构建逐字节一致；入口 gzip 必须 < 100KB（2026-10-25 的启动崩溃就是 Node 侧全绿、Chromium 侧语法错，这道闸专门守这个缝）

另有一道**性能门槛** `tools/check-perf.mjs`（D3）：跑 `tools/bench.mjs` 的八体系样本，对首次 150ms / p50 10ms / p95 25ms / 带解析 250ms / 1000 盘 4000ms / RSS 800MB 判超限，CI 同样执行。阈值按文档目标留 5–10 倍余量，拦的是数量级回退而非毫秒级抖动；慢机用 `DSH_PERF_SCALE=3` 按倍数放大上限。`npm run bench` 只测量不判错，用来做改动前后的 A/B 对比。

结果卡顶部还有一行**首屏耗时**（D1+）：`首屏 42ms｜引擎 18ms（首次加载）· 排盘 9ms`。数字是这一次在本机的实测——面板从点击到两帧后计时，独立页量「组 HTML + 写 DOM」的同步时间（不含浏览器真正绘制的那一帧）；引擎那段的「首次加载 / 已缓存」来自分块缓存状态。只在本机显示，不上报、不发网络请求；缺哪段省略哪段。

`client.js` 与 `client.<name>.js` 都是构建产物，不要手改。入口只带界面；面板按当前 tab 用 `require.async` 取引擎分块，首次打开不再下载整套引擎。改动记录见 [CHANGELOG.md](CHANGELOG.md)。

### 发版

```bash
# 先在 npm 生成 Granular Token：Read and write + 勾 Bypass 2FA
NPM_TOKEN=npm_xxx npm run release              # 正式发布（会先跑测试与构建校验）
NPM_TOKEN=npm_xxx npm run release -- --dry-run # 只校验不发布
NPM_CLI=/path/to/npm-cli.js NPM_TOKEN=... npm run release   # 本机没有 npm CLI 时
node tools/release.mjs --verify-only           # 只核对 registry 上当前版本的附件
```

脚本会拦下：工作区不干净、`client.js` 未随源码重建、registry 上已有同版本；发布后自动核对新版本与 `dist-tags`，并提示补 `git tag`。

**发失败 / 核对失败怎么办**：`release.mjs` 在这两条失败路径上会打印回滚步骤（把 `latest` 指回上一版、`deprecate` 问题版本、网页 2FA 删包、升补丁号、CHANGELOG 改回未发布段；打过 tag 时另有删 tag 两步），但**不自动执行**。同样的步骤可以单独取：

```bash
node tools/release-rollback.mjs --version 0.57.1 --previous 0.57.0 --reason verify-failed
NPM_TOKEN=... node tools/release-rollback.mjs --version 0.57.1 --previous 0.57.0 --apply dist-tag
```

`--apply` 只支持 `dist-tag`（把 `latest` 指回上一版）；`unpublish` / `deprecate` / 删远程 tag 属于共享状态变更，脚本只打印命令，由人确认后执行。

**发布后为什么要看附件，而不是只看 `npm publish` 的输出**：npm 的发布是异步的，版本条目会先出现在 packument 里（连 shasum、签名、`latest` 都齐），tarball 附件却可能晚几分钟才落盘。这中间别人 `npm i` 会撞 404，而 `npm publish` 早就打印了成功。所以 `tools/verify-publish.mjs` 的判据是四条：tarball 返回 200、下载到的字节 sha1 与 registry 记的 `shasum` 一致、`fileCount` 对得上、包里该有的文件（`package.json`/`client.js`/`命理排盘.html`）确实在。15 分钟内一直对不上就判定失败并给出处置路径。

另外记一条实操限制：`unpublish`/`deprecate` 属于「绕过 2FA 的破坏性动作」，granular token 会被 403 拒绝（`Granular access tokens that bypass two-factor authentication may not perform this action`），这类动作只能在 npm 网页上用 2FA 做；真要撤版，把版本号升一个补丁号重发通常更快。

### 样式命名约定

面板的 CSS 是以 `<style>` 注入到宿主页面的，**没有 shadow DOM 隔离**，所以每个类名都带命名空间前缀，避免和宿主页面的同名元素互相染色：

| 前缀 | 归属 |
|---|---|
| `pp-` | 紫微盘骨架（宫格、宫位选中、三方四正、身宫） |
| `bz-` | 四柱八字表（干支大字、藏干、十神、五行旺衰） |
| `dt-` | 宫位详情面板 |
| `flow-` | 流月 / 流日 / 流时 |
| `ct-` / `ft-` | 盘心 / 盘脚 |
| `mp-` | 各模块根容器：`mp-it`（解析）、`mp-dl`（六壬）、`mp-hy`（六爻）、`mp-mh`（梅花）、`mp-tt`（塔罗）、`mp-hex`（爻线）、`mp-trib`（体用） |
| `hb-` / `tritag-` | 卦盒 / 体用标签 |
| `dl-` / `ss-` / `ssx-` / `ssg-` | 六壬盘块 / 神煞族 |
| `ask-` | 所问之事回显 |

两条硬规矩：

- **不用泛词做类名**（`.body`、`.big`、`.s`、`.p`、`.on`、`.it` 这类）。名字越泛，越容易在同一个文件里被两处语义共用——本项目已经栽过两次：`.pp-body` 同时是「整块视图容器」和「身宫格」，一次导致身宫整格消失，另一次的 `::after` 残骸在页面左上角飘出一个孤立的「身」方块。
- **模块根类名必须带前缀**。裸用的 `.it` / `.dl` / `.hy` 一旦注入全局，宿主页面的同名元素会被一起改写。

*2026-10 做过一轮全量整改：199 个类名按语义分组补齐前缀（约 540 处替换），计算逻辑一行未动，20 组断言与全量视口扫描全绿。*
