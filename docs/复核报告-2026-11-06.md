# dsh-metaphysics 复核报告（2026-11-06）

对象：`metaphysics-bundle` 0.62.2（`engine/` 66 个模块、26,613 行）。
范围：以八字/历法为主（四柱、五行生克、十神、藏干、纳音、旬空、长生、大运、胎元命宫、节气、农历），旁及黄历与六爻装卦。

## 一、必须先修的 3 处

### P1 取格：透干按「柱位」找，没按「藏干角色」找 —— 约 10% 的盘格局取错（已修复）

**位置**：`engine/geju.js:119-125`（`monthPattern`）

```js
const others = ['year', 'month', 'hour'];
const exposedKey = others.find((k) => cands.some((c) => c.stem === pillars[k].stem));
const use = exposedKey ? cands.find((c) => c.stem === pillars[exposedKey].stem) : (hui || base);
```

**现象**：`戊戌 甲寅 丙子 癸巳`（2018-02-13 10:00）排出「食神格」，evidence 写着「月令寅藏甲丙戊，余气戊（食神）透于年干」。同一盘的月干是**甲**——寅的本气、丙火的偏印，明明白白透在月柱上，却被跳过。

**成因**：`others` 的顺序是「年→月→时」，取到第一个透出者就停。这里年干戊（余气）先被命中，本气甲（月干）根本没参与比较。子平取格的口径是「月令本气透则取本气，本气不透再取中气、余气」，与柱位先后无关。

**影响面**：1990–2020 抽 1,116 盘，**13.4%**（150 盘）存在「两处以上不同藏干同时透出」，其中 **74%（111 盘）取到的不是本气**——即约每 10 盘就有 1 盘格局名与通行取法不同。格局是 `yongshenOf` 的输入，连带用神、喜忌、行运评分、解读文案全偏。

**修正建议**（按角色优先，报柱位时月干优先）：

```js
const EXPOSE_KEYS = ['year', 'month', 'hour'];
// cands 的顺序就是 本气 → 中气 → 余气，谁先透出用谁
const exposed = cands.find((c) => EXPOSE_KEYS.some((k) => pillars[k].stem === c.stem));
// 文案定位：月干最贴近月令，优先报月
const exposedKey = exposed ? (['month', 'year', 'hour'].find((k) => pillars[k].stem === exposed.stem)) : null;
const use = exposed || hui || base;
const usedBy = exposed ? '透干' : (hui ? '会支' : '本气');
```

**验证方式**：
1. 上述命例 `primaryName` 必须是「偏印格」；
2. 结构断言：扫描 200 盘，凡「本气透出」（月支本气出现在年/月/时任一干），`primary` 的十神必须等于本气十神——现在这条会挂 100+ 例；
3. 抽样跑 `frame.geju`，与「本气 → 中气 → 余气」手工表逐盘比对。

### P2 黄历：用「正午」判交节，交节当天月建还算上个月 —— 每年约 6 天，建除/值神/月柱全错（已修复）

**位置**：`engine/almanac.js:199`（`jdNoon`）、`:205`（年柱）、`:216`（月建）、`:234`（节气显示）；`engine/zeri.js:184` 逐日调用 `buildAlmanac`，**择日整块继承**。

```js
const jdNoon = partsToJd({ year, month, day, hour: 12, minute: 0 });
...
if (t.jd <= jdNoon) prevJie = t;       // 月建
const ganzhiYear = jdNoon < lichunJd ? year - 1 : year;   // 年柱
```

**现象**（2020-02-04，立春 17:03）：

| 项 | 本插件 | 通行黄历 |
|---|---|---|
| 月柱 | 丁丑 | 戊寅 |
| 建除 | 建 | 闭 |
| 值日星神 | 朱雀 | 明堂 |

同一页还写着「下一个节气：立春 2020-02-04（今天）」——节气说今天是立春，月柱却仍是丑月，自相矛盾。

**成因**：黄历是「按日」的产物，却拿当日**正午**去跟交节时刻比。交节若在午后，正午时还没交节，于是整天仍算上一个月。12 个「节」里约一半落在午后（17:03、22:10 这类），这些日子就整年错 6 天左右。

**影响面**：2020–2030 抽「交节日 + 次日」264 天，**现状错 69 天**。受影响的不只是显示：月建是建除十二神、黄道黑道值神、月建类神煞、择日宜忌的共同输入。

**修正建议**：黄历侧改成「日序」比较，八字侧继续用精确时刻（八字必须精确到分，不能跟着改）：

```js
const jdn = toJDN(year, month, day);
const dayOf = (jd) => Math.floor(jd + 0.5);
if (dayOf(t.jd) <= jdn) prevJie = t;        // 月建：交节日当天即属新月
const ganzhiYear = dayOf(lichunJd) <= jdn ? year : year - 1;
```

**验证方式**：
1. 按上述改法模拟同一批 264 天，错误数 69 → **0**（已实测）；
2. 回归用例：`2020-02-04` 断言 月柱 戊寅、建除 闭、值神 明堂，且 `jieQi.prev.name === '立春'`；
3. 新增 fixture：2020–2030 全部交节日的（建除、值神）与寿星表一致。

### P3 「巳」的藏干中气/余气与自身司权表相反 —— 五行占比与通根权重偏一档（已修复）

**位置**：`engine/bazi.js:23`、`engine/geju.js:29`；对照 `engine/bazi.js:39` 的 `RENYUAN_TABLE`。

```js
巳: ['丙', '戊', '庚'],                  // 角色被标成 本气丙 / 中气戊 / 余气庚
巳: [['戊', 5], ['庚', 9], ['丙', 16]],  // 司权：戊 5 日、庚 9 日、丙 16 日
```

**现象**：本仓库自己的司权表里庚 9 日、戊 5 日，庚才是中气；但藏干表把庚标成余气。同一套规则在另外三个「长生」支上是一致的——寅（甲**丙**戊，丙为长生/中气）、申（庚**壬**戊，壬为长生/中气）、亥（壬**甲**，甲为长生/中气），唯独巳反过来。寿星/tyme 与 lunar-javascript 均作 **丙庚戊**。

**成因**：巳的藏干表沿用了「丙戊庚」这一派的书写顺序，却按索引位置直接赋权重（`WUXING_HIDDEN_WEIGHT = [1, 0.5, 0.3]`、`ROOT_HIDDEN_WEIGHT = [1.2, 0.6, 0.3]`），于是戊拿 0.5、庚拿 0.3，与司权天数正好颠倒。

**影响面**：凡四支见巳，五行统计 土 −0.2 / 金 +0.2；日主为庚辛者通根 −0.24，日主为戊己者 +0.24；藏干十神列表的角色标注也随之偏。例：`1990-05-12 14:30`（庚午 辛巳 丁丑 丁未）现输出 土 3.0 / 金 2.6，应为 土 2.8 / 金 2.8。

**修正建议**：两处改为 `巳: ['丙', '庚', '戊']`；更稳的做法是让藏干顺序从 `RENYUAN_TABLE` 派生（按「本气 → 中气 → 余气」的角色定义取），避免两张表再次走散。

**验证方式**：
1. 断言 `巳` 藏干为 `['丙','庚','戊']`，且 12 支藏干与寿星表一致（fixture 固化）；
2. 结构断言：对本气/中气/余气三角色的分支，「中气」的天数或长生位不得低于「余气」；
3. 回归上述命例的五行数值。

## 二、两处口径不自洽（不会天天错，但会把边界样本排成另一张盘）

### P4 节气用「北京地方平时」、出生时刻按「东八区」——1929 年前差 14 分钟

**位置**：`engine/calendar.js:157/160/164/205`（1929 前切到 7.7611 h）；`engine/bazi.js:274-287`（`applyTrueSolar` 以 120°E 为基准，即把输入当东八区）。

**现象**：`1920-02-05 10:15` → 本插件 庚申年 戊寅月（立春算 10:12）；寿星 己未年 丁丑月（立春 10:26）。**年柱、月柱同时不同。**

**成因**：交节时刻按「1929 年前 = 北京地方平时（116.4°E）」换算，出生钟点却按 120°E 解析，两端差 14.3 分。1900–1928 全部 696 个节气与寿星稳定差 **14.2 分**（现代段只差 0.1 分，说明不是星历问题，是时区口径）。

**影响面**：1900–1928 出生、且落在交节前后 14 分钟内的人，月柱（连带年柱）提前翻。农历未受影响（1901–2099 共 72,684 天 0 差异，14 分钟不足以移动朔日）。

**修正建议**（二选一，推荐 A）：
- **A（推荐）**：节气/农历统一用东八区，删掉 `CUTOVER_JD` 分支。与主流排盘软件、寿星一致，客户端不需要额外解释。
- **B**：保留历书口径，但把 1929 年前的输入时刻也按北京地方平时解释（`partsToJd` 加 14.3 分），并在面板注明「1929 前按北京地方平时」。

**验证方式**：对拍 1900–1928 的 696 个节气，偏差 <1 分；加边界用例 `1920-02-05 10:15` 断言与寿星一致；跑一遍农历全区间确认仍 0 差异。

### P5 ΔT 在 2101 年后成了常数 —— 2200 年偏 5 分、2400 年偏 15 分

**位置**：`engine/calendar.js:137-151`（`knots` 止于 `[2100, 110.0]`，之后 `return knots[last][1]`）。

**现象**：立春相对寿星：2200 年 **+5.1 分**，2400 年 **+14.7 分**。引擎自报支持到 2400 年，`zeri`/黄历也吃这个区间。

**成因**：ΔT 的线性表只到 2100，之后一律 110 秒；实际 ΔT 到 2200 约 250 s、2400 约 400 s。

**修正建议**：把 knots 延到 2200/2300/2400（或接 Meeus 长期式 / NASA 多项式，2100 后按 50 年一档内插）。

**验证方式**：2200、2300、2400 三个锚点的节气与寿星差 <2 分，写成单测。

## 六、复现方式

对拍脚本用 `tyme4ts@1.5.5`（`npm i tyme4ts@1.5.5`）：

```js
import { SolarDay, SolarTime, SolarTerm, SixtyCycle, ChildLimit, Gender } from 'tyme4ts';
SolarDay.fromYmd(2000, 1, 1).getSixtyCycleDay().getName();        // 日柱
SolarTime.fromYmdHms(1990,5,12,14,30,0).getLunarHour().getEightChar(); // 四柱/胎元/命宫
SolarTerm.fromIndex(2026, 3).getJulianDay().day;                  // 节气（0=冬至）
ChildLimit.fromSolarTime(t, Gender.MAN).getStartDecadeFortune();   // 起运
```

本轮各项数字（73,415 天日柱、4,824 个节气、72,684 天农历等）均由一次性脚本跑出，未写入仓库，避免把第三方依赖带进 CI。
