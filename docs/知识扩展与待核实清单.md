# 知识扩展与待核实清单

> 这份清单对应 `engine/interpret-knowledge.js`（40 条规则条目）。
> 每条规则在解析卡片里直接显示，右上角标注可信度：**诸家一致 / 各家有异说 / 待核实**。
> 立这道门槛的原因很简单：命理领域最容易犯的错不是「算错」，而是「说得很确定，却没人知道依据在哪」。

## 一、状态口径

| 状态 | 含义 | 展示方式 |
|---|---|---|
| 诸家一致 | 传统诸家说法基本一致，可直接作为断法依据 | 灰绿标签，可直接引用 |
| 各家有异说 | 存在不同流派，本插件取其中一派 | 琥珀标签 + 「注」写清分歧在哪 |
| 待核实 | 本插件尚未完整实现，或需以原始典籍核对后再用 | 红色标签 + 文末「尚未实现（不猜）」单列 |

**硬约束（由 `test/interpret-knowledge.test.mjs` 守住）**：每条必须有出处（≥6 字）、机制解释（≥30 字）、一句话白话；`variant` / `todo` 必须写 note 说明分歧；全库禁止出现「一定 / 必然 / 注定 / 百分百」这类绝对化表述。

## 三、待核实清单（下一步要补的硬骨头）

### 1. 六爻应期（`liuyao-yingqi-exact`）

- **现状**：只给「时间窗口」的方向提示，不给具体日期。
- **缺什么**：用神旺衰 × 动变 × 旬空出空 × 日月冲合 的多层加权，各家优先级还不同。
- **为什么先不做**：给一个看起来精确、实则拍脑袋的日子，比留白更糟。
- **怎么做才算过**：《卜筮正宗》卦例里有明确应验日期的条目，先建 20 条以上的应期对拍集，命中率与偏差分布都公开，再决定是否输出。

### 2. 八字起运交运日（`bazi-dayun-jiaoqi`）

- **现状**：三日折一年、一日折四月、一时辰折十天，算到年月，不含交运当日的时辰细分。
- **影响面**：大运交接年份在边界处可能相差一年内。
- **怎么做**：补交运日的时辰级推算，并用已知案例（起运年龄与交运年的公开案例）核对。

### 3. 需要「原始典籍核对」的 13 条异说

优先级最高的三条（争议最大、最容易被误用）：

| 条目 | 争的是什么 | 本插件当前取法 |
|---|---|---|
| 月令人元司权分日 | 中气余气各主几日（7/7/16、9/3/18 等多说） | 只取「本气当权」，不细分日数 |
| 调候与扶抑谁优先 | 冬夏生人是否先看调候 | 两者同时给出，不替你定优先 |
| 岁运并临吉凶 | 「并临主大凶」是否成立 | 只作「变动提示」，不断吉凶 |

核对方式：以《子平真诠》《穷通宝鉴》《三命通会》原文逐条比对，每条记「原文在哪一卷、怎么说的、我们取哪一句」，形成可查的引文索引。

## 四、可继续扩展的方向

按「信息密度 ÷ 成本」排序：

1. **八字**：十神组合的细分（官印相生、食伤生财的具体成立条件）、从格与假从的判别、胎元命宫身宫的实际用法。
2. **紫微**：星曜组合（紫府同宫、机月同梁）的成立条件与破格条件、流月流日的取用；飞星串连已做到「单一支化逐宫追到成环」，还差三件——三方四正一起飞的复合飞化、串连叠大限流年算力重、自化忌与其他三化互见的取象。
3. **六爻**：用神多现的取舍权重、卦身与世应的关系（语料里没有「卦身」字样，缺对拍依据，留白）；化进化退现只标趋势，尚未叠月建日辰算实际力重；卦体只做了「卦/爻」两类伏吟反吟，尚未把卦体与用神旺衰联动（同一支六冲，近病主速愈、久病主凶，这层要月建数据才判得了）。
4. **奇门**：十干克应（100 组天盘干加地盘干的成象与断语，文本量大、各家措辞不一，需先定底本再上）；六仪、八门、九星的入墓（与三奇入墓口径不同，需逐条核）；天盘干的旺衰（现只算门与星，干与宫的生克未折成五态）；用神落宫与击刑/入墓/旺衰的联动，目前只并列条件、未推结论。
5. **通用**：把「知识条目」与已录的 128 条卦例打通——凡被典籍案例证伪的条目，状态自动降级并记录。

## 五、维护约定

- 新增条目必须同时给出 `gist`（≤48 字）、`detail`（≥30 字）、`source`、`status`；`variant` / `todo` 必须写 `note`。
- 改条目文案后跑 `node tools/test-all.mjs`，质量门会自动检查出处、长度、绝对化用词。
- 条目 id 一旦发布不要改名（前端与对拍脚本会按 id 引用），改内容可以，改 id 等于新增。
