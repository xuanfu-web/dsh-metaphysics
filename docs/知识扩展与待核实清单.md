# 知识扩展与待核实清单

> 这份清单对应 `engine/interpret-knowledge.js`（51 条规则条目）。
> 每条规则在解析卡片里直接显示，右上角标注可信度：**诸家一致 / 各家有异说 / 待核实**。
> 立这道门槛的原因很简单：命理领域最容易犯的错不是「算错」，而是「说得很确定，却没人知道依据在哪」。

## 一、状态口径

| 状态 | 含义 | 展示方式 |
|---|---|---|
| 诸家一致 | 传统诸家说法基本一致，可直接作为断法依据 | 灰绿标签，可直接引用 |
| 各家有异说 | 存在不同流派，本插件取其中一派 | 琥珀标签 + 「注」写清分歧在哪 |
| 待核实 | 本插件尚未完整实现，或需以原始典籍核对后再用 | 红色标签 + 文末「尚未实现（不猜）」单列 |

**硬约束（由 `test/interpret-knowledge.test.mjs` 守住）**：每条必须有出处（≥6 字）、机制解释（≥30 字）、一句话白话；`variant` / `todo` 必须写 note 说明分歧；全库禁止出现「一定 / 必然 / 注定 / 百分百」这类绝对化表述。

> 0.24.0 的六冲 / 六合 / 反吟 / 伏吟四条，判定全部由 `engine/liuyao.js` 的纳甲地支实配推出，对拍集是 `test/fixtures/classics.json` 里 23 条断语含这四个词的卦例（逐条例题见 `test/liuyao-body.test.mjs`）。

> 0.27.0 的化进 / 化退两条，由「同五行地支顺次」推出八对（寅卯、巳午、申酉、亥子，土丑辰未戌成环），对拍集是同一份语料里 12 条断语含「化进 / 化退 / 进神」的卦例（见 `test/liuyao-jintui.test.mjs`）；土之进退次序各家不完全一致，故第二条标 `variant`。
> 0.50.5 的喜忌重叠：`engine/geju.js` 的 `yongshenOf` 原先在「调候优先」时把 `climate.avoidElement` 直接插进 `avoid`，若该五行已在扶抑 `favor` 中（偏弱燥盘的火、偏强寒湿盘的水），同一行会同时出现在喜与忌；摘要看似正常，面板 / 解读 / 筛选各取一份，用户就会看到「一会儿喜火、一会儿忌火」（GitHub issue #1）。现改为：所忌已在喜用则不插 `avoid`，记入 `disputed`（元素 / 扶抑角色 / 气候），新增 `disputedTenGods`；`detail`、摘要「用神」「寒暖」、解读「用神」「寒暖」、白话、面板用神行与寒暖卡统一标「有争议」。不改旺衰与调候判断，只禁止同一行同时判喜判忌；216 盘扫描无交集。`test/yongshen-disputed.test.mjs` 钉住两张真实争议盘、无冲突盘、广扫、四处可见与白话 / 解读一致。
> 0.37.0 的三命通会一条：`engine/classics.js` 只录与格局取用直接相关的七条（论正官 / 正财 / 印绶 / 食神 / 伤官 / 阳刃 / 建禄，卷五、卷六），`test/sanming.test.mjs` 逐条核 id、卷次、典藏网章节链接与原文关键字，并把七个格「子平真诠在前、三命通会在后」的选取钉住。标 `variant` 的原因：两书成书年代与流派不同，同一个格的取法与用语有出入；本插件并列两说、不合并，也不做校勘改字。
> 0.29.0 的飞星两条：飞化只认宫干四化表（中州派），串连只跟同一支化逐宫跳、满 12 步或回到走过的宫即停，48 条飞化与四条链全部由 `test/ziwei-fly.test.mjs` 独立录入的四化表核过（见该文件的 ①~⑥ 组）。标 `variant` 的原因：飞星派与三合派对「宫干飞化要不要看、看几跳」说法不同，庚干四化亦有两套（本插件取太阳禄/武曲权/太阴科/天同忌）。
> 0.33.0 的干宫生克一条：`engine/qimen.js` 的 `stemPalaceRelation(stem, palace)` 只吃「天干五行 + 洛书宫五行」，`test/qimen-gan.test.mjs` 用天干五行与宫五行重新推导 10 干 × 9 宫 = 90 组全部复算，并扫 60 个真实盘逐宫核 `stemElement` / `stemRelation` / `stemState`（含中五宫）。标 `variant` 的原因：各家对「干与宫」的取象宽窄不一，有只论干宫、有连十干克应一并论；本插件只判干与宫，十干克应 100 组未做。
> 0.32.0 的交运一条：放大口径是「出生到起运侧节令的真实天数 × 365.2422/3」，同一条比例就是古法「三日折一年、一日折四月、一时辰折十日」；每步大运在同月同日同时刻换，闰日退到 2 月 28 日。`test/bazi-jiaoyun.test.mjs` 用 `partsToJd` 独立复算偏移、核顺逆取哪一节、八步相接与每步 10 年，并拿 1987-10-10 那盘（交运 1988-02-29 → 十年后 1998-02-28）钉住闰日退位。标 `variant` 的原因：各家对「一年折几日」取法不一（本插件固定回归年 365.2422 日，按 360 日折算的流派会差一两天），出生时刻或经度一变交运日也会前后移一两天。
> 0.38.0 的岁运提示：`engine/bazi.js` 给每条流年加 `suiyun`——`dayun` 列出与「该年立春到次年立春」区间相交的大运（交运落在年内时前后两步并列），`signals` 只出四类：岁运并临（当值大运与流年干支相同）、运年反吟（两者天克地冲）、流年伏吟（流年与年/月/日/时柱干支相同）、流年反吟（流年与某柱天克地冲）。`test/suiyun.test.mjs` 不复用引擎判定，按「月柱干支顺逆推八步」与「立春区间相交」两套独立写法复算 10 张盘 × 10 年，并构造同干相冲（丙子 vs 丙午，不算反吟）、起运前（无大运）、年内交运（两步并列）三条边界。摘要/解析/白话/面板四处可见。仍标「各家有异说」：岁运并临是否主凶、伏吟反吟要不要分轻重，各家分歧很大；本插件只标干支事实，不折分数、不判吉凶，也不逐年标大运与原局之间的伏吟反吟。

- 新增条目必须同时给出 `gist`（≤48 字）、`detail`（≥30 字）、`source`、`status`；`variant` / `todo` 必须写 `note`。
