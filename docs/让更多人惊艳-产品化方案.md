# 让更多人「惊艳」的产品化方案

> 核心判断：**惊艳不来自再加第九个体系，而来自把这个领域最缺的两样东西做出来——「看得见」和「可验证」。**
> 命理工具满地都是，人人都在比功能多少；没人敢把自己的盘拆开给人问责。
> 这恰好是这个项目已经有、但还没亮出来的底牌。

---

## 一、诊断：三个断点，卡在不同人群

| 人群 | 卡在哪 | 现状 |
|---|---|---|
| 路人（潜在用户） | **看不到** | 要装 DeepSeek Harness 才能见到面板；README 是一堵功能墙，前 200 字读完仍不知道长什么样 |
| 玩家（会算的人） | **看不懂** | 输出是一屏结论，「为什么是这个六亲/这个世应/这个旬空」无从追问，只能选择信或不信 |
| 同行（会验的人） | **不敢信** | 没有对拍报告、没有失败案例、没有可复现凭证——和满地的黑箱 App 无法区分 |

三件事分别对应：**可及性 → 可解释性 → 可验证性**。按这个顺序做，投入产出最高。

---

## 二、六个动作（按性价比排序）

### ① 把「零安装实例页」推到台前（可及性，最高优先）

**现在就有**：`node tools/build-html.mjs` 产出 373KB 单文件 HTML，引擎与界面全内联，双击即开、无网络依赖。
**缺的是三件事**：

1. **一个链接**：部署成在线页（Harness 站外可打开），首屏就是可操作的排盘界面。
2. **3 秒上手**：预置 4 个示例（名人公开生日 / 经典卦例 / 一张紫微盘 / 一张奇门盘），点一下就出盘；再给「排我的盘」一键填入当天时间。
3. **分享卡片**：`<title>` + `og:title/og:description/og:image`，转发到群/微博时显示的是「一张紫微盘缩略图」而不是文件名。

**验收**：陌生人不看文档，从点开链接到看见第一张盘 ≤ 3 次点击；页面无外部请求（`check-patterns` 已有纯净性检查可扩展）。

**成本**：低（1 天）。**影响**：把「要先装一个 IDE 插件」的漏斗损耗直接抹掉。

---

### ② 口径差异一键对照（可解释性，同行最痛）

**一句话卖点**：「流派之争我们不藏起来——换个口径，盘上变的是哪几个字，一眼看到。」

现在的口径开关（晚子时 / 真太阳时 / 拆补·超神接气·置闰 / 闰月按本月或次月）都在，但切换后用户只看到结果变了，不知道**哪里**变。

**做什么**：`engine/diff.js` —— 用同一组参数跑两次 `compute`，做结构化差异（逐柱 / 逐爻 / 逐宫），面板把变化的字高亮成「旧值 → 新值」，并在顶部一句话总结：「本次切换影响：月柱、时柱；其余不动」。

**为什么惊艳**：这是专业用户天天吵架的点，却是所有工具的盲区。谁会主动暴露自己的口径分歧，谁就赢得专业信任。

**验收**：四组开关各出一张 diff，变化项与人工核对一致；无变化时明确显示「本盘不受此口径影响」。

**成本**：低-中（2–3 天，可复用 `test/baseline.test.mjs` 的对比思路）。

---

### ③ 典籍对拍徽章 + 公开失败清单（可验证性，信任核弹）

**一句话卖点**：「《卜筮正宗》138 例逐爻对拍：对上 121 例，剩下 17 例是原文漏录或版本异文，页码与理由全部列出。」

**素材已经在一半**：拆卦例流水线（卦名讹字规范、动爻数推导、纳甲/六亲/伏神/旬空校验、每条带出处与排除理由）正在跑。

**做什么**：
1. `tools/gen-verification.mjs`：读卦例数据集 → 产出 `docs/verification.html`（可筛选：全部 / 一致 / 剔除+理由）。
2. README 顶部一枚徽章：`典籍对拍 121/138 · 明细可查`，点进报告页。
3. 数据集进 `test/fixtures/`，成为回归测试的一部分——**报告不是一次性营销物料，是每次 CI 都会跑的活数据**。

**为什么惊艳**：行业里没人公布自己算不对的例子。「敢把失败案例连页码一起摊开」这件事本身，比任何功能都有说服力。

**验收**：报告页数字与 `npm run test:ci` 输出一致；任一卦例判定改变会让 CI 红。

**成本**：中（3–5 天，依赖 138 条录完）。

---

### ④ 推导链：每个字都能点开问责（可解释性，最深护城河）

**一句话卖点**：「点一下『父母』，它告诉你：剥卦属乾宫五世 → 世在五爻 → 乾属金 → 未土生金 → 故为父母；伏神取本宫首卦同位。」

**做什么**（六爻先行，规则最密、收益最大）：
1. 引擎返回体加 `trace`：`{ field, rule, inputs, result, source }`，不改变现有字段。
2. 面板右侧抽屉渲染推导链，逐级可展开；底层落到「规则名 + 出处」（京房八宫 / 纳甲表 / 旬空定式）。
3. 再逐步推到八字（旺衰分值、格局判定）、紫微（格局命中条件）。

**为什么惊艳**：把黑箱变成玻璃箱。学习者拿它当教材，同行拿它当靶子——两者都会替你传播。

**验收**：六爻盘的 6 爻 × (世应/纳甲/六亲/伏神) 都能点开且与规则表自洽；关掉抽屉不影响任何现有布局（`test/layout.test.mjs` 守住）。

**成本**：中-高（5–8 天）。

---

### ⑤ 影子盘：可复现的分享凭证（传播性）

**一句话卖点**：「同一张盘，两个人打开必须一模一样；不一样就是 bug，我们把差异摆出来。」

**做什么**：`engine/fingerprint.js` —— 由 `(system, 归一化参数, seed, asOf, 引擎版本)` 生成短 ID（如 `LY-7F3K9Q`），面板可复制；打开该 ID 时若版本不同，自动展示「逐字 diff」。

**为什么惊艳**：给了「对盘」这件事一个客观基准，把玄学讨论拉回可验证的地面。

**验收**：同参数任意次、任意机器生成同 ID；改一个参数 ID 必变；版本 diff 能定位到具体字段。

**成本**：中（3 天）。

---

### ⑥ 公开工程账本（差异化人设，成本最低）

README 顶部三个数字，随 release 自动更新：

```
1152 条断言 · 45 个测试文件 · 1000 盘 264ms
```

再加一句：「改坏一条断言，CI 就红。」命理插件里有 CI 五道闸、断言基线、性能基准的，目前只有这一个。

**成本**：半天。**影响**：给「可验证」这个主张提供工程侧背书。

## 三、落地顺序（两周版）

| 周 | 动作 | 产出 |
|---|---|---|
| 第 1 周 | ① 在线实例页 + ⑥ 工程账本 | 一个可转发的链接 + README 三数字 |
| 第 2 周 | ② 口径 Diff | 「同盘三口径」对照截图（最佳传播素材） |
| 第 3 周 | ③ 对拍报告（依赖 138 条录完） | 徽章 + 公开失败清单 |
| 第 4 周起 | ④ 推导链（六爻）→ ⑤ 影子盘 | 玻璃箱 + 可复现凭证 |

---

## 四、三条「证据型」传播素材（比任何宣传语都好用）

1. **《同一张盘，三种流派差在哪》**——口径 Diff 截图，三个字被高亮。专业群必转。
2. **《我们对上了 121 例，剩下 17 例是书的问题》**——附页码的失败清单。可信度一击必杀。
3. **《给命理插件上了 CI：改坏一条断言就红》**——1152 条断言的截图。技术圈会当成「玄学也能工程化」的案例转。

---

## 五、明确不做

- **不再加第九个体系**：功能已过密，边际收益趋零，反而稀释「可验证」这个主张。
- **不做 AI 断吉凶**：与「不构成医疗/投资/法律判断」的免责声明冲突，且会摧毁专业信任。
- **不做账号体系/云存储**：本地计算与隐私是这个项目的立身之本，一旦上云就失去最强差异点。

---

## 六、一句话概括

> 别人在比「我算得多」，这个项目该比「我算得能被查验」——
> 把单文件实例页放出去让人摸到，把口径差异摊开让人吵，把失败案例连页码一起公布让人信。
