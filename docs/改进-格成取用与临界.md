# 格成不真、取用分层、临界提示

三件事看起来不相关，其实是同一个毛病：引擎说的每句话都可能被读成「对我这个人下的判决」。
成格分被读成命好不好，取用被读成该补什么、不该补什么，强弱档被读成分数。修的都不是算法，
是**算法结论出口处那句话**——所以三个改动全都落在「解读层 + 面板 + 测试」这三处，引擎的判定值一个没动。

---

## 一、格成不真 ≠ 命不好

### 问题在哪

`patternScoreOf()`（`engine/geju.js:269`）只返回 `grade: '成格' | '不成格'`，
解读层原样写成「成格评分 20/100（不成格）」。60 分线是我们按课里的模板定的阈值，
它量的是「结构像不像模板」，用户读到的是「我这个人不行」。

### 改法

把两层拆开，并且在**每一处会出现 grade 的地方**都带一句两层说明——不能只写在折叠的细节里，
只有展开的人看得到的提示等于没写。

| 位置 | 改动 |
| --- | --- |
| `engine/geju.js:217-227` | 新增 `PATTERN_LAYERS`：`school`（贵格标准量什么）、`life`（人生判断看什么）、`pass` / `fail` / `outer` 三种结论措辞 |
| `engine/geju.js:patternScoreOf` | 成格、不成格、外格三条返回路径都带 `layers: {school, life}` 与 `verdict` |
| `engine/interpret.js:351` | 框架段格局行改口径：成格写「说的是这条路走得顺，别当成富贵的判词」，不成格写「这是贵格标准的结论，不是命差的结论」 |
| `engine/interpret.js` 格局依据条 | 追加三行：`两层分开看——贵格标准：…／人生判断：…／结论：…` |
| `engine/interpret-plain.js:buildPlain` | 新增 `psPlain`，把「不成格不等于命差」放进首屏那段说人话 |
| `src/panel-kit.js` 格局区 | chips 下面加一行 `成格分 不成格 20/100 + verdict`，分数旁边就是那句话 |

**不改 `grade` 的取值**：`成格 / 不成格` 是课里的术语，盘面事实该保留原词。错的不是取值，是解释。

三种结论的措辞区别：
- 成格：说明结构走得顺、位置感强；它量的是结构不是结果。
- 不成格：只说明「按贵格模板没套上」，不是命差。成格分低只代表这条路不当主角，路还在别处——大运、行业与自己的选择都在评分之外。
- 外格（建禄／羊刃／月劫）：课里不按正八格计分，谈不上「成不成格」，别拿评分当人生结论。

### 实测

壬水未月盘（1996-07-14 男）：`不成格 20/100` →
> 不及 60 分线作不成格论：这只说明「按贵格模板没套上」，不是命差。成格分低只代表这条路不当主角，不代表没有路——大运、行业与自己的选择都在评分之外。

2018 盘（`偏印格 70/100 成格`）→ `过 60 分线作成格论：说明这条结构走得顺、位置感强。它量的是结构不是结果——富贵与否不在这张分表上。`

## 二、取用纳入制杀 / 化杀

### 问题在哪

`favor / avoid` 只按强弱给（`engine/geju.js:743-744`，weak / strong / 中和三支），
而 `tacticsOf()`（`engine/geju.js:672`）早就算出了「食伤制杀（局中无印可化）」。
结果是同一份输出里「取用手法：食伤制杀」与「忌土火」并排站着——用户不知道信哪个，
而且**多半会走向食伤制杀**：因为 favor 里印是空的，杀印相生这条路在数组里根本不存在。

### 改法：加一层组合标注，不动 favor / avoid

| 位置 | 改动 |
| --- | --- |
| `engine/geju.js` | 新增导出 `combinationOf({tactics, gods})`：按 `tactics.key` + 十神分量，把每一路拆成 `{role, action, note}` |
| `engine/geju.js:yongshenOf` | `const combination = combinationOf({tactics, gods})`，`detail` 加一句「组合取舍：…」，返回值带 `combination` |
| `engine/interpret.js` 取用手法条 | 末尾追加逐行明细 `官杀——忌（无可化之路）：…` + 一条口径说明 |
| `src/panel-kit.js` 喜忌区 | disputed 下面加组合 chips：`/忌|慎用|耗身/` → warn 色，`/^(用|可化|可用)/` → ok 色 |

六种组合各自的行（`role → action`）：

| 组合 | 官杀 | 印 | 食伤 | 财 | 比劫 |
| --- | --- | --- | --- | --- | --- |
| 杀印相生 `sha-yin` | 可化 | 用（枢纽） | 慎用 | — | — |
| 食伤制杀·身弱 `shi-sha`+弱 | 忌（无可化之路） | 优先补 | 短期可用·长期耗身 | — | — |
| 食神制杀·身强 `shi-sha`+强 | 可用（贵气） | — | 用（制杀） | — | — |
| 财生官杀 `cai-guan` | 可用（可担） | — | 偏轻 | 用（生官） | — |
| 伤官配印 `shang-yin` | — | 用（收） | 已过 | — | — |
| 比劫帮身 `bi-cai` | — | — | — | 可用（需分担） | 用（合力） |

### 为什么不直接改 favor / avoid

行运评分、流年吉凶档位全都读这两个数组。为了把官杀从「忌」里拿掉而改数组，
等于连带改掉未来每一年的吉凶——一句话的收益，几十年的账。

所以组合层只做标注：告诉用户「这一路该怎么算」，不去碰计分输入。
这条口径写在 `combination.note` 里，也进了测试（`favor` 长度仍是 3）。

真要让组合影响行运，得先设计「制杀成功 / 失败」的判据（印有没有力、食伤会不会反过来耗身），
不是一句话的事，列在「没做的」里。

### 实测

壬水未月盘：`tactics = 食伤制杀（局中无印可化）`，组合层 →
`官杀 忌（无可化之路）／食伤 短期可用·长期耗身／印 优先补`。
这条盘以前只会告诉你「食伤制杀」，现在会顺带说清「印是缺的那一块，补印不等于补杀」。

## 三、临界提示

### 问题在哪

旺衰**不是连续分数切档**，是三要素是非判定的真值表（`engine/bazi.js:629-643`，得令／得地／得势 → 五档），
`score`（`bazi.js:645` 的 `total`）只作展示。用户看到「中和 2.1 分」会自然按分数理解——
差 0.3 就该偏强，凭什么是中和。

这条争议出在真值表结构本身，不是用户理解错。所以提示要讲清两件事：
**离翻档差多少、卡在哪个门槛**。

### 改法

| 位置 | 改动 |
| --- | --- |
| `engine/bazi.js` | 新增模块级 `levelOf(judges)`（原真值表整体搬进去，判定逻辑一个字没改）与 `boundaryOf(judges, level)` |
| `engine/bazi.js:compute` | `const {level, basis} = levelOf(judges)`；`const boundary = boundaryOf(judges, level)`；`strength.boundary` 挂进结果 |
| `engine/interpret.js:347` | 日主行尾加 `**档位临界**：…`（仅 near 时） |
| `engine/interpret-plain.js:buildPlain` | 说人话层加 `bd` 一句 |
| `src/panel-kit.js:3545` 前 | `临界·离偏强 0.3 分` chip，挂在「日主强弱」那一行前面 |

`boundaryOf` 的做法：逐个门槛翻一次（`di-up` 通根 1.0、`di-down`、`shi-up` 净帮扶 0、
`shi-down`、`ling-down` −1.5），每翻一次重跑 `levelOf` 看档位会不会变；变了才收进 `candidates`。
`BOUNDARY_NEAR = 0.5` 以内算 `near`。返回：

```
{ near, level, candidates[], nearest: {key, from, to, toBasis, gap, by}, plain, note }
```

`by` 字段直接说卡在哪：「净帮扶再加 0.3 就到得势门槛，现在 -0.3（门槛 0）」——
这比「差 0.3 翻档」有用，用户知道往哪边使力。

原来的 `strength.edges`（`bazi.js:650-653`）保留，它服务 `engine/trend.js:126` 的走势曲线；
`boundary` 是新的一层，服务解读与面板。

**只在 near 时输出**：都发提示等于没提示，还会让「临界」两个字贬值。

### 实测

| 盘 | 档位 | near | nearest |
| --- | --- | --- | --- |
| 1996-07-14 广州 | 中和 2.1 | true | `shi-up → 偏强` gap 0.3 |
| 1988-01-20 北京 | 中和 1.6 | true | `shi-up → 偏强` gap 0.5 |
| 2000-06-06 上海 | 中和 2.5 | true | `di-up → 偏强` gap 0.1 |
| 1990-05-12 成都 | 身强 5.5 | false | — |

## 没做的（留给下一轮）

1. **那两处口径不一致**（正文「最需要火」vs 用神行「忌土火」；调候取丙火 vs 穷通宝鉴取辛金）——
   按你说的留给你处理，本轮没碰。
2. **组合层没有回头影响行运评分**。要接进去得先定「制杀成功 / 失败」的判据（印有力无力、食伤是否反过来耗身），
   现在只标注不计算。
3. **临界提示只做了旺衰档**。成格分也有 60 分线，离 60 只差一两分时同样会有人问「凭什么是 20 不是 62」——
   同一套 `boundaryOf` 思路可以平移到 `patternScoreOf`，但要先定减项的可翻转范围。
