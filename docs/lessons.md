# lessons：踩过的坑

每条要有三样：**错在哪**、**为什么会错**、**下次怎么防**。没有第三样的不算 lesson，只是抱怨。

教训不等于规矩。要变成「必须这么干」的，另立一条进 `rules.md`。

条目格式：

```
## L-00N 标题
- type: lesson
- status: active | superseded
- at: YYYY-MM-DD
- 防再犯：固化成哪个脚本 / 哪条测试
```

## L-001 漏最后一步重建，195/196 是行尾不是漏构建

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：`tools/check-eol.mjs` + `.gitattributes` 兜底（R-001 / R-003）

现象：同一个 commit 在 CI 绿、在本机红、在新 worktree 红得更厉害。当时的判断是「改完 CHANGELOG 忘了重建 client.js」，方向错了。

真因：`docs/verification.html` 盘上 375861 字节、生成器输出 370146 字节、含 5715 个 `\r\n`。`.gitattributes` 只钉了 js/mjs/json/md，漏了 html 与 svg，`core.autocrlf=true` 的机器一 checkout 就把产物转成 CRLF。

为什么会看错：先看到「红」，再找最像的原因（漏构建），没有先量字节与行尾。定性顺序错了。

防法：兜底规则一行 `* text=auto eol=lf`；行尾闸同时查「产物本身」和「规则在不在」——只查产物的话，规则被删时本机仍然绿，换机器才炸。

## L-002 测试绿 ≠ 产品可见

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：合盘列为 `ENVELOPE_ONLY`，并把 22 体系实机排一遍纳入验收

合盘的 adapter 算出了分数，测试全绿，但 `interpret()` 在更早的地方就 return 了——用户那边什么都不显示。测试断言的是「adapter 有输出」，不是「结果区有内容」。

防法：验收里加一条「实机把 22 个体系各排一次，结果区字数 > 0」。断言要卡在最终渲染，不卡中间产物。

## L-003 断言写反了还是绿的

- type: lesson
- status: active
- at: 2026-11-14
- 防再犯：`ok()` 的第二个参数必须能失败；关键闸补「故意改坏必须变红」的自测

`ok(label, condition)` 的第二参数写成常量或恒真表达式，测试永远 PASS。有几次把条件写成了字符串（非空即真）。

防法：`tools/verify-tests-can-fail.mjs` 那种「先改坏再跑」的自测要覆盖关键闸门。新写测试时先想一句「它在什么情况下会红」，答不上来就是没测到东西。

## L-004 分块架构：模块进块 ≠ 能用

- type: lesson
- status: active
- at: 2026-11-14
- 防再犯：新模块同时登记 `ORDER` 与 `INTERPRET`（R-007）

模块被打包进块了，但它跨模块解构的依赖没在同一个块里，调用时才炸；`catch` 一吞就变成 `null`。症状极具迷惑性：**面板静默缺一块，单页完全正常**。

防法：定位时自建最小宿主仿真（假 React + `__ModuleLoader__` + 真 client.js）在本地复现，比反复让人重启快得多。

## L-005 改宿主 UI 显示，先找渲染它的组件

- type: lesson
- status: active
- at: 2026-11-13
- 防再犯：改任何显示文案前先确认数据源

DSH 插件市场的条目名读 `package.json` 的 `meta.title`，但**侧栏那行不是它**——侧栏是插件自己注册的 `sidebar.panellist` label，在 `src/app.js` 末尾硬编码 `label: () => '命理 v' + window.__MP_VER`。改 `meta.title` 完全没效果。两处来源，两处都要改。

## L-006 断言绑当天日期，隔夜必红

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：所有取「今天」的用例显式传 `datetime`

`facts-only.test.mjs` 有一条断言写死「癸巳日」，六爻 case 没给 `datetime`，引擎按当天算：11-15 是癸巳全绿，11-16 变甲午就挂。重启后第一条红的就是它。

防法：测试里出现「今天」的地方一律显式传日期；任何依赖系统时钟的断言都算定时炸弹。

## L-007 pwsh 内联替换中文静默失败

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：改中文用 `edit` 工具或写成 node 脚本

`pwsh -Command` 里 `.Replace('中文','别的')` 会不出声地不生效（编码在命令行边界上就已经错了）。同类的还有 `node -e` 里带中文引号被 PowerShell 吃掉，报 `SyntaxError: Unexpected token '<eof>'`。

防法：改文件内容走 `edit` 工具；批量替换写一个 `.mjs` 临时脚本再删。

## L-008 文档里写自己的提交短哈希，amend 就失效

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：文档只写「在哪个标签/哪次提交上跑过」，必要时留全哈希

短哈希在 amend 之后指向一个不存在的对象，读者按它复现会失败。要么写全哈希，要么写标签名（`baseline/pre-interact` 这种不会变的）。

## L-009 缓存键不能「按当时的表单重算」

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：默认盘存「出盘那刻的键」，不重算（F-004）

第一版给默认盘算键时，用档案里的出生字段重新拼参数。跑实机才发现必错：写缓存那次用的键包含完整表单（`question / cross / juMethod / lines / spread / verifyPast` 都在 `collectArgs()` 里），刷新后这些控件回 HTML 默认值，重算出来的哈希与写进去的永远对不上——默认盘于是每次打开都重排，正好踩中任务书 1.5 第四条禁止项。

防法：**键跟着「那次排盘」走，不跟着「现在表单长什么样」走**。置顶时把 `castKey` 反查成键存进 `defaultChart`。

## L-010 长任务别在本会话里等

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：`Start-Process` 后台 + 轮询日志

pwsh 单次调用 300s 超时，超时会丢进程，前面跑的成果全没（`check-assertions --update` 就这样被打断过一次，基线没更新）。全量测试串行时尤其危险。

防法：长任务用 `Start-Process` 起后台进程、输出重定向到文件，再按需轮询日志。或者先把并发池做出来，让任务本身短到不会超时。

## L-011 这台机器装 sh 钩子会把提交全堵死

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：装钩子前先探 sh（`tools/hooks-install.mjs` 已内置），闸门逻辑放 `tools/preflight.mjs`

按常规做法写了 `.git/hooks/pre-commit`（`#!/bin/sh` + 调 node），装完第一次 commit 直接失败：

    fatal error - couldn't create signal pipe, Win32 error 5

sh 根本没起来，脚本一行都没跑到。这不是「检查没生效」，是 **git 认为钩子执行失败 → 拒绝这次提交**。同一台机器上 `sh -c "echo ok"` 也报同样的错，所以在 DSH 沙箱进程上下文里 msys 起不来是环境限制，不是脚本写错。

防法：①安装器先 `sh -c "echo ok"` 探活，不通就拒绝安装；②真正的闸门代码放 node 脚本（`tools/preflight.mjs`），钩子只做 `exec`，这样 sh 正常的环境和这台机器跑的是同一套逻辑；③`SKIP_HOOKS=1` 留作逃生门。

## L-012 只读上线后 e2e 连红三次，根子是同一个

- type: lesson
- status: active
- since: 2026-11-16

加了「出盘后参数区只读」之后，`tools/e2e-panel.mjs` 先后在三处 `.fill()` 报
`element is not editable`（时间框、合盘对方生日、真太阳时那一组）。第一次我按红点一个个补
解锁，补一处跑一次、跑一次几十秒，来回三轮。

错在哪：把「一个行为变化影响所有填表点」当成了「三处互相独立的红」。

防再犯：这类成片红，第一个念头应该是「谁把它们连在一起」。正确做法是一次性把所有
`.fill/.check/.uncheck/.selectOption` 前都加上 `unlockParams()`（38 处，未锁时是 no-op），
一轮就绿。

## L-013 五分之三的体系没有「说人话」，测试一直是绿的

- type: lesson
- status: active
- since: 2026-11-16
- 防再犯：`test/plain-five.test.mjs`；验收里「22 体系各排一次」提升为「并检查 plain 是否出现」

`engine/interpret-plain.js` 的 `buildPlain()` 只实现了 bazi / ziwei / liuyao，其余体系走到
函数末尾 `return ''`。渲染侧写的是 `it.plain ? '<div class="mp-it-plain">…' : ''`——空串
就整块不渲染。结果是奇门、塔罗、大六壬、梅花、合盘的用户那边少一整段，控制台无报错、接口
无异常、全闸一路绿。

错在哪：把「函数有返回值」当成了「功能存在」。空串在 JS 里是合法返回值，它不会抛，
也不会被类型检查拦。

为什么测试没发现：写测试的时候想的是「这段别崩」，没有人写「这段必须出现」。少一块是
最容易漏的回归型——它不制造红，只制造沉默。

防法：①每个「可选块」都要有一条「该出现时必须出现」的正向断言，不能只测「不崩」；
②关键渲染分支的兜底值（`''` / `null`）要么在断言里点名，要么在类型上不可达；
③术语先翻译再输出——`父母` 在六爻里是文书流程，在用户脑子里是家里人。

## L-014 交互里的「提前 return」会把人锁死在计算中

- type: lesson
- status: active
- since: 2026-11-16
- 防再犯：`test/required-fields.test.mjs` 断言 run 里唯一的裸 return 是缓存命中出口

22 体系巡检发现：农历转公历在农历日期为空时，`run()` 里写的是
`el('out').innerHTML = '<div class="err">…</div>'; return;`——**直接 return，没走 bail**。
结果状态停在 `CALCULATING`，`#go` 的 `disabled` 与 `aria-busy` 再也没人恢复。用户点一次
这个页面就废了，只能刷新。

两秒内读两次状态都是 `CALCULATING`，按钮永久灰——这不是慢，是死了。

错在哪：把「给用户一句提示」和「把机器恢复到可操作状态」当成了一件事。提示只是副作用，
真正必须做的是复位 `flowState`、摘 `aria-busy`、重算按钮可用性。

顺带查出另外两个同源问题：起名缺名字、报数起课缺数字都没被 `validateForm` 拦住，一路
冲进引擎，用户看到的是「请给 givenName（1–2 个汉字）」和「缺数请向用户索要，不要代填」——
后一句根本是写给 AI 的。

防法：①`run()` 里所有提前退出只能有一个出口 `return bail(msg)`，bail 负责复位；
②`validateForm` 要按「当前模式」覆盖到每个体系的必填，不是只查日期；
③引擎的错误文案是给调用方看的，界面必须在它之前拦住——用户的界面不该出现参数名。
## L-015 说人话要「指得回盘面」，不是把话说长

2c 正文细化第一版，八字那段只写了「底子偏足、抗压能力好，学会收力比使劲更重要」。
读着顺，但用户对着四柱找不到这句从哪来——它其实是把 `strength.level` 换了个说法，
属于把标签念一遍，不是解释。

改法：把结论拆成能一眼对回盘面的三件事——月令哪一地支、本气是哪个十神、地支里哪几处是根、
年/月/时三干里哪几处往外耗。紫微同理（命宫坐什么星、亮不亮、三方四正哪几宫、煞星压哪），
六爻（世应各在哪爻、动爻化进还是化退、空亡与反吟压哪半），奇门（日干落哪宫坐什么星门、
时干落哪宫、值符值使在哪、十干应克撞没撞上）。

两个坑：

①**加位置就要减空话**。M2 是 400 字预算，不是 400 字目标。加了「说到具体位置」那 60 字，
就得把「传统上把它当作变化感强一点的提示，既不是好消息也不是坏消息」这类不针对本盘的句子
压掉，否则一撞线就得砍真内容。同一段里把化进讲两遍也要砍。

②**术语翻译分长表和短表**。一句话里塞两三个六亲时用长译（「文书、答复、流程与长辈」）
直接把首屏撑长，要另备一张短译（「文书流程」）。宫位的数字也要跟全篇统一成中文
（「阴遁三局」旁边写「七宫」，不写「7宫」）。

防法：写盘面位置段时先问一句——这句话里的每个名词，用户能不能在盘上指出对应的那一格。
指不出的就是标签，不是解释。
