# lessons：踩过的坑

每条要有三样：**错在哪**、**为什么会错**、**下次怎么防**。没有第三样的不算 lesson，只是抱怨。

教训不等于规矩。要变成「必须这么干」的，另立一条进 `rules.md`。

条目格式：

```
## L-00N 标题
- type: lesson
- status: active | superseded
- at: YYYY-MM-DD
- 防再犯：固化成哪个脚本 / 哪条测试
```

## L-001 漏最后一步重建，195/196 是行尾不是漏构建

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：`tools/check-eol.mjs` + `.gitattributes` 兜底（R-001 / R-003）

现象：同一个 commit 在 CI 绿、在本机红、在新 worktree 红得更厉害。当时的判断是「改完 CHANGELOG 忘了重建 client.js」，方向错了。

真因：`docs/verification.html` 盘上 375861 字节、生成器输出 370146 字节、含 5715 个 `\r\n`。`.gitattributes` 只钉了 js/mjs/json/md，漏了 html 与 svg，`core.autocrlf=true` 的机器一 checkout 就把产物转成 CRLF。

为什么会看错：先看到「红」，再找最像的原因（漏构建），没有先量字节与行尾。定性顺序错了。

防法：兜底规则一行 `* text=auto eol=lf`；行尾闸同时查「产物本身」和「规则在不在」——只查产物的话，规则被删时本机仍然绿，换机器才炸。

## L-002 测试绿 ≠ 产品可见

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：合盘列为 `ENVELOPE_ONLY`，并把 22 体系实机排一遍纳入验收

合盘的 adapter 算出了分数，测试全绿，但 `interpret()` 在更早的地方就 return 了——用户那边什么都不显示。测试断言的是「adapter 有输出」，不是「结果区有内容」。

防法：验收里加一条「实机把 22 个体系各排一次，结果区字数 > 0」。断言要卡在最终渲染，不卡中间产物。

## L-003 断言写反了还是绿的

- type: lesson
- status: active
- at: 2026-11-14
- 防再犯：`ok()` 的第二个参数必须能失败；关键闸补「故意改坏必须变红」的自测

`ok(label, condition)` 的第二参数写成常量或恒真表达式，测试永远 PASS。有几次把条件写成了字符串（非空即真）。

防法：`tools/verify-tests-can-fail.mjs` 那种「先改坏再跑」的自测要覆盖关键闸门。新写测试时先想一句「它在什么情况下会红」，答不上来就是没测到东西。

## L-004 分块架构：模块进块 ≠ 能用

- type: lesson
- status: active
- at: 2026-11-14
- 防再犯：新模块同时登记 `ORDER` 与 `INTERPRET`（R-007）

模块被打包进块了，但它跨模块解构的依赖没在同一个块里，调用时才炸；`catch` 一吞就变成 `null`。症状极具迷惑性：**面板静默缺一块，单页完全正常**。

防法：定位时自建最小宿主仿真（假 React + `__ModuleLoader__` + 真 client.js）在本地复现，比反复让人重启快得多。

## L-005 改宿主 UI 显示，先找渲染它的组件

- type: lesson
- status: active
- at: 2026-11-13
- 防再犯：改任何显示文案前先确认数据源

DSH 插件市场的条目名读 `package.json` 的 `meta.title`，但**侧栏那行不是它**——侧栏是插件自己注册的 `sidebar.panellist` label，在 `src/app.js` 末尾硬编码 `label: () => '命理 v' + window.__MP_VER`。改 `meta.title` 完全没效果。两处来源，两处都要改。

## L-006 断言绑当天日期，隔夜必红

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：所有取「今天」的用例显式传 `datetime`

`facts-only.test.mjs` 有一条断言写死「癸巳日」，六爻 case 没给 `datetime`，引擎按当天算：11-15 是癸巳全绿，11-16 变甲午就挂。重启后第一条红的就是它。

防法：测试里出现「今天」的地方一律显式传日期；任何依赖系统时钟的断言都算定时炸弹。

## L-007 pwsh 内联替换中文静默失败

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：改中文用 `edit` 工具或写成 node 脚本

`pwsh -Command` 里 `.Replace('中文','别的')` 会不出声地不生效（编码在命令行边界上就已经错了）。同类的还有 `node -e` 里带中文引号被 PowerShell 吃掉，报 `SyntaxError: Unexpected token '<eof>'`。

防法：改文件内容走 `edit` 工具；批量替换写一个 `.mjs` 临时脚本再删。

## L-008 文档里写自己的提交短哈希，amend 就失效

- type: lesson
- status: active
- at: 2026-11-15
- 防再犯：文档只写「在哪个标签/哪次提交上跑过」，必要时留全哈希

短哈希在 amend 之后指向一个不存在的对象，读者按它复现会失败。要么写全哈希，要么写标签名（`baseline/pre-interact` 这种不会变的）。

## L-009 缓存键不能「按当时的表单重算」

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：默认盘存「出盘那刻的键」，不重算（F-004）

第一版给默认盘算键时，用档案里的出生字段重新拼参数。跑实机才发现必错：写缓存那次用的键包含完整表单（`question / cross / juMethod / lines / spread / verifyPast` 都在 `collectArgs()` 里），刷新后这些控件回 HTML 默认值，重算出来的哈希与写进去的永远对不上——默认盘于是每次打开都重排，正好踩中任务书 1.5 第四条禁止项。

防法：**键跟着「那次排盘」走，不跟着「现在表单长什么样」走**。置顶时把 `castKey` 反查成键存进 `defaultChart`。

## L-010 长任务别在本会话里等

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：`Start-Process` 后台 + 轮询日志

pwsh 单次调用 300s 超时，超时会丢进程，前面跑的成果全没（`check-assertions --update` 就这样被打断过一次，基线没更新）。全量测试串行时尤其危险。

防法：长任务用 `Start-Process` 起后台进程、输出重定向到文件，再按需轮询日志。或者先把并发池做出来，让任务本身短到不会超时。

## L-011 这台机器装 sh 钩子会把提交全堵死

- type: lesson
- status: active
- at: 2026-11-16
- 防再犯：装钩子前先探 sh（`tools/hooks-install.mjs` 已内置），闸门逻辑放 `tools/preflight.mjs`

按常规做法写了 `.git/hooks/pre-commit`（`#!/bin/sh` + 调 node），装完第一次 commit 直接失败：

    fatal error - couldn't create signal pipe, Win32 error 5

sh 根本没起来，脚本一行都没跑到。这不是「检查没生效」，是 **git 认为钩子执行失败 → 拒绝这次提交**。同一台机器上 `sh -c "echo ok"` 也报同样的错，所以在 DSH 沙箱进程上下文里 msys 起不来是环境限制，不是脚本写错。

防法：①安装器先 `sh -c "echo ok"` 探活，不通就拒绝安装；②真正的闸门代码放 node 脚本（`tools/preflight.mjs`），钩子只做 `exec`，这样 sh 正常的环境和这台机器跑的是同一套逻辑；③`SKIP_HOOKS=1` 留作逃生门。

## L-012 只读上线后 e2e 连红三次，根子是同一个

- type: lesson
- status: active
- since: 2026-11-16

加了「出盘后参数区只读」之后，`tools/e2e-panel.mjs` 先后在三处 `.fill()` 报
`element is not editable`（时间框、合盘对方生日、真太阳时那一组）。第一次我按红点一个个补
解锁，补一处跑一次、跑一次几十秒，来回三轮。

错在哪：把「一个行为变化影响所有填表点」当成了「三处互相独立的红」。

防再犯：这类成片红，第一个念头应该是「谁把它们连在一起」。正确做法是一次性把所有
`.fill/.check/.uncheck/.selectOption` 前都加上 `unlockParams()`（38 处，未锁时是 no-op），
一轮就绿。

## L-013 五分之三的体系没有「说人话」，测试一直是绿的

- type: lesson
- status: active
- since: 2026-11-16
- 防再犯：`test/plain-five.test.mjs`；验收里「22 体系各排一次」提升为「并检查 plain 是否出现」

`engine/interpret-plain.js` 的 `buildPlain()` 只实现了 bazi / ziwei / liuyao，其余体系走到
函数末尾 `return ''`。渲染侧写的是 `it.plain ? '<div class="mp-it-plain">…' : ''`——空串
就整块不渲染。结果是奇门、塔罗、大六壬、梅花、合盘的用户那边少一整段，控制台无报错、接口
无异常、全闸一路绿。

错在哪：把「函数有返回值」当成了「功能存在」。空串在 JS 里是合法返回值，它不会抛，
也不会被类型检查拦。

为什么测试没发现：写测试的时候想的是「这段别崩」，没有人写「这段必须出现」。少一块是
最容易漏的回归型——它不制造红，只制造沉默。

防法：①每个「可选块」都要有一条「该出现时必须出现」的正向断言，不能只测「不崩」；
②关键渲染分支的兜底值（`''` / `null`）要么在断言里点名，要么在类型上不可达；
③术语先翻译再输出——`父母` 在六爻里是文书流程，在用户脑子里是家里人。

## L-014 交互里的「提前 return」会把人锁死在计算中

- type: lesson
- status: active
- since: 2026-11-16
- 防再犯：`test/required-fields.test.mjs` 断言 run 里唯一的裸 return 是缓存命中出口

22 体系巡检发现：农历转公历在农历日期为空时，`run()` 里写的是
`el('out').innerHTML = '<div class="err">…</div>'; return;`——**直接 return，没走 bail**。
结果状态停在 `CALCULATING`，`#go` 的 `disabled` 与 `aria-busy` 再也没人恢复。用户点一次
这个页面就废了，只能刷新。

两秒内读两次状态都是 `CALCULATING`，按钮永久灰——这不是慢，是死了。

错在哪：把「给用户一句提示」和「把机器恢复到可操作状态」当成了一件事。提示只是副作用，
真正必须做的是复位 `flowState`、摘 `aria-busy`、重算按钮可用性。

顺带查出另外两个同源问题：起名缺名字、报数起课缺数字都没被 `validateForm` 拦住，一路
冲进引擎，用户看到的是「请给 givenName（1–2 个汉字）」和「缺数请向用户索要，不要代填」——
后一句根本是写给 AI 的。

防法：①`run()` 里所有提前退出只能有一个出口 `return bail(msg)`，bail 负责复位；
②`validateForm` 要按「当前模式」覆盖到每个体系的必填，不是只查日期；
③引擎的错误文案是给调用方看的，界面必须在它之前拦住——用户的界面不该出现参数名。
## L-015 说人话要「指得回盘面」，不是把话说长

2c 正文细化第一版，八字那段只写了「底子偏足、抗压能力好，学会收力比使劲更重要」。
读着顺，但用户对着四柱找不到这句从哪来——它其实是把 `strength.level` 换了个说法，
属于把标签念一遍，不是解释。

改法：把结论拆成能一眼对回盘面的三件事——月令哪一地支、本气是哪个十神、地支里哪几处是根、
年/月/时三干里哪几处往外耗。紫微同理（命宫坐什么星、亮不亮、三方四正哪几宫、煞星压哪），
六爻（世应各在哪爻、动爻化进还是化退、空亡与反吟压哪半），奇门（日干落哪宫坐什么星门、
时干落哪宫、值符值使在哪、十干应克撞没撞上）。

两个坑：

①**加位置就要减空话**。M2 是 400 字预算，不是 400 字目标。加了「说到具体位置」那 60 字，
就得把「传统上把它当作变化感强一点的提示，既不是好消息也不是坏消息」这类不针对本盘的句子
压掉，否则一撞线就得砍真内容。同一段里把化进讲两遍也要砍。

②**术语翻译分长表和短表**。一句话里塞两三个六亲时用长译（「文书、答复、流程与长辈」）
直接把首屏撑长，要另备一张短译（「文书流程」）。宫位的数字也要跟全篇统一成中文
（「阴遁三局」旁边写「七宫」，不写「7宫」）。

防法：写盘面位置段时先问一句——这句话里的每个名词，用户能不能在盘上指出对应的那一格。
指不出的就是标签，不是解释。

## L-016 取不到值要当作缺陷，别当「这句可省」

奇门「说人话」里拼「你（日干甲）落几宫」时，`byStem('甲')` 永远找不到——甲在奇门里不落地，
遁在六仪里（甲子戊、甲戌己、甲申庚、甲午辛、甲辰壬、甲寅癸）。代码写成 `if (dz) bits.push(...)`，
于是甲午日、甲X 时柱的盘静默少一句，页面不报错、测试全绿（样本恰好是癸巳日、丁巳时）。
用户看到的是「这件事（时干…）落八宫」，却不知道自己站哪，这句正是最该有的一句。

错在两层：一是把「取不到值」当成了可省分支（`if (x)` 兜底），没问过它为什么会取不到；
二是测试样本只挑了一个日期，没覆盖天干为甲的那六分之一。

修法：`locate(st, gz)` 在 `st === '甲'` 时按柱地支查 `YI` 表换成旬首仪再去地盘找宫。
防法：凡是 `if (x) 输出一句` 的写法，都要能回答「x 什么时候必然为空、那时用户少了什么」；
再补一条用甲日盘做样本的断言（`test/plain-five.test.mjs` 里那 2 条），别让样本偏巧躲开。

## L-017 「所以呢」不是补一段话，是把盘面自带的顺序翻成动作

2c 第二刀给塔罗 / 大六壬 / 梅花 / 合盘补「所以呢」。写之前先看这四个体系的盘面字段，
发现它们本来就带先后或轻重：`cards[].position` 是牌位顺序，`sanChuan` 是初→中→末，
梅花是 本卦→互卦→变卦，合盘的 `dimensions[].score` 已经标了哪一维偏紧。

所以这层的正解不是另编一套「建议」，是**把盘面已有的那一格点出来，给一个能落手的下一步**：
塔罗落在现在/建议位、大六壬按三传当时间线、梅花落在动爻、合盘落在偏紧那一维。
时间窗也不许编：梅花明确写「不给几号」，合盘写「下一次一起拿主意」，都不填月份。

两个坑：

①**措辞不能写死某一种牌阵**。原来塔罗收尾是「过去改不了，往后还没到」，三张牌阵通顺，
五张牌阵（现状/阻碍/建议/结果/潜在）里读不通——「最值得先看的是建议这张」后面接「过去改不了」。
改成从 `now` 与 `next` 两个牌位取词，单张、三张、五张共用一条。顺带发现 `interpret()` 的
verdict.headline 在 five 牌阵里仍写「3张牌里2正1逆」、factors 只按前三张算，这是 envelope 侧的
同源问题，另记在台账，不混进这一刀。

②**「所以呢」层只替换收尾句，前面的盘面描述别动**。第一刀（e9cf81e）已经把四主力的位置段
写进去了，这一刀要保持 `说人话 = 描述盘面 + 所以呢` 的结构；重写整段会把已经过闸的位置段
又洗一遍，M2 与测试都白测。护栏按「落到哪一格 + 给得出下一步 + 不下定论」三条写死，
断言一律拿 `r` 的字段反查（牌名、地支、互卦名、偏紧维的 label），写死样本值等于没接上盘面。

防法：动这类文案前先跑一次 `node tools/metrics.mjs` 记下 M2 基线；改完比一遍四行字数。
这次四行变化：梅花 151→172、大六壬 159→182、塔罗 141→146、合盘 191→188，最大仍 271（六爻），
离 400 上限有余；`client.js` gzip 124100 / 上限 128000，余量 3900 字节，没撞体积线。

## L-018 两条链各写一份白名单，早晚会漂——收成标记类，顺便把测试从「守字面串」改成「守契约」

**症状**：问事层（所问之事 / 询问方向）该不该跟着参数一起锁，单页按 id 认 `#question` /
`#direction`，面板按 class 认 `.mp-askbox` / `.mp-askblock` / `.mp-askonly`。同一件事写两处，
0.82.0 巡检里就漂过一次：面板的放过列表只有 `.mp-askbox`，`.mp-askblock` 漏了，
「所问之事」出盘后变 readOnly，`onBlur → refreshInterpret` 成了永远触发不了的死代码。
加一个新问事控件，得记得改两处；漏一处是「出盘后改不了问法」或者「问事框被一起锁死」。

**修法**：`src/panel-kit.js` 出 `pp.ASK_FREE` 与 `pp.lockParams(root, locked)`——
名单一份、readOnly/disabled 的取舍一份、`mp-askfree` 标记类作为契约。两条链各自只负责
「传哪个根节点」和「切自己那个 locked class」：单页 `syncInputLock()` 传 `.bar`，
面板 useEffect 传 `.mp-panel`。单页的两个控件在 `tools/build-html.mjs` 模板里挂上标记类，
面板的 `.mp-askonly` 这类本来就是样式类，一并列进名单。共用层没就绪时单页保守全锁，
不赌哪几个是问事层。

**顺手学到的更要紧一条**：静态测试守字面串，重构时必然误报。这次 `test/ask.test.mjs` 三条
正则写死 `<textarea id="question" rows="2"`，加一个 class 就红；`test/panel-cache.test.mjs`
第三节在面板源码里数 `n.closest('.mp-askbox…')`，逻辑一搬到 panel-kit 全红。功能都没坏，
红的是测试自己。改法不是放宽正则，是换断言对象：
- 模板串 → `/<textarea id="question"[^>]*mp-askfree[^>]*rows="2"/`，把「该带的标记」写进断言；
- 源码逻辑 → 守「面板确实把锁定交给共用层、不再自己 querySelectorAll」+「共用层名单含三类」，
  两句话各断在真正该守住的那一层。

**判据**：一条静态断言红的时候，先问「是行为坏了还是我把实现搬了家」。搬家就让断言跟着搬，

- type: lesson
- status: active
- since: 2026-11-17

**错在哪**：一次外部巡检抓到四个，全是「看起来正常、其实换了口径」：

1. 小六壬只给 `num1–3` 时，工具层仍补上「此刻」的钟点，引擎再默认 `mode: 'time'`，

`chart_id` 当初按「出生类体系」的字段清单写的，抽牌类体系是后加的，键表没跟着扩；

**下次怎么防**：
- 缺省值只有两种写法：不替用户决定，或者把「我替你决定了什么」写进结果（如 `meta.mode`）。
  互斥入参都给了又不指明时，报 E_INPUT，别挑一组继续算。
- 「同盘同 ID」的键表要按体系逐项核：凡能改变盘面的入参（抽牌结果、牌阵、种子、口径开关）
  都进键；新增体系时先问一句「这张盘靠什么区分」。
- 文档里的承诺必须有**行为断言**：调用一次、断言结果里出现的日期/模式，字符串存在不算。
  清单与台账同理——`check-ledger` 类扫描可以后补，但每条承诺先得有能红的断言。

**实测**：`test/args.test.mjs` 模式推断 10 条、`test/guard-inputs.test.mjs` ㉒㉓ 16 条、
`test/adapters-extra.test.mjs` ⑧ 11 条；全闸 207/207、11521 断言。

## L-022 变量写给自己也是「写错了」：`--env-x:var(--env-x)` 让一整行声明作废，而且不报错

- type: lesson
- status: active
- since: 2026-11-17

**错在哪**：结论卡上三枚判断标签——「能成」「要看条件」「两头都有」——在浅色主题下颜色完全一样。
查了半天以为是配色没调，实际是两处叠加：

1. 令牌写成 `--env-good:var(--env-good)`。按 CSS 规则，自定义属性允许自引用，但解析到自身时
   整条声明无效（invalid at computed-value time）→ `color:var(--env-good)` 拿不到值，退回继承墨色。
2. 就算写对了也取不到：这套令牌挂在 `.pp,.mp-it,.mp-al,…` 那一长串选择器上，而结论卡
   `.mp-env-head` 是它们的兄弟、不在里面。加 `var()` 兜底（`var(--env-good,var(--muted))`）
   只会让它「看起来像灰字」，把问题藏得更深。

**为什么没被发现**：三枚标签同色，肉眼读作「设计就是这么素」，而所有断言当时都在查 `.pp` 作用域内的
对比度——作用域外的变量根本没进检查清单。CSS 变量失效不抛错、不写日志，只安静地少一层语义。

**下次怎么防**：
- 写 `--x:var(--x)` 这类自引用，等于写了个空值；同义检查用 `rg -- '--([a-z-]+):var\(--\1\)'`。
- 变量定义的作用域要和**使用点**对齐：结论卡这类兄弟节点，令牌落到 `:root` 更省心；深色另给
  `@media screen and (prefers-color-scheme:dark){:root{…}}`。
- 语义色（好 / 留意 / 另一种）必须落成断言：不是自引用、`:root` 有定义、深色有覆盖、三色彼此分得开。
  只查对比度会漏掉「三色同色」这种情况——三种灰都过 AA，但语义全丢了。

**实测**：`src/panel-kit.js` 在 `:root` 给 `#2f6b4f` / `#7d5410` / `#3a5570`（`--card` 上 5.8–7.6:1，
最大通道差 33），深色一套同名覆盖；页面里 `.mp-env-dir.t-alt` 由 `rgb(26,25,22)` 回到 `rgb(58,85,112)`；
`test/explain-quality.test.mjs` 加 4 条钉住，全闸 209/209、11586 断言。

## L-023 把 CSS 塞进模板字符串：反引号会截断它，外层全局规则会漏进来

搬动一批标题（`div` → `h2` / `h3`）时踩到两处，都不在同一层，却都不报错或报得很远。

**坑一：模板字符串里的注释带反引号**。`src/panel-kit.js` 的整块 CSS 是 `const CSS = \`…\``，
我在注释里写了 `h3{display:flex}` 这样带反引号的句子——反引号直接结束模板字符串，后面整段变成
非法表达式。这份文件本身是 ESM，`import` 时才炸；而测试里有一批文件把 CSS 抠出来塞进 `vm.runInNewContext`
编译，于是报错出现在六份 `ziwei-*.test.mjs` 里，**报的是「Unexpected identifier」，指向的是测试，不是 CSS**。
要不是这一批测试当场红，这个错误会一路走到构建：`build-html` 里 `${CSS}` 插值同样会炸，只是晚一步。

**坑二：页面外壳的全局 `h3` 规则会漏进嵌入区**。`tools/build-html.mjs` 给「方法与验证」段写了
`h3{display:flex;align-items:center;gap:10px}`，它是裸元素选择器，不认边界——报告里的每个 `h3`
都被它套上，分节标题和 `[n]` 角标被挤成同一行。本地 CSS 之后加载，`margin` / `font-size` 能覆盖，
**`display` 没人声明就继承**，所以只在浏览器里看得出来，源码里什么都看不到。

**下次怎么防**：
- 在模板字符串里写 CSS，注释里一律不用反引号（用「」引住选择器）。这条同样适用于在任何 `\`…\`` 里写注释。
- 换标签前先 `rg` 一遍**裸元素选择器**（`h1{` / `h3{` / `p{` / `table{`），确认它们会不会漏到你要改的块；
  嵌入区一律给显式的 `display`，别指望「没说就是默认」。
- 改完必须在浏览器里量 computed style：`tagName / display / margin / fontSize / fontWeight` 逐项对，
  CSS 层面读源码判断不出「变量是否解析、全局规则是否命中」。

**实测**：`h3.mp-env-adv-h` / `h3.mp-it-sh` / `h3.mp-outline-h` 显式回 `display:block`，`.mp-env-risk`
的 h3 保持 `inline`（它是行内标签）；页面里九个标题 computed 全部 `margin:0`，字号字重与改前一致
（结论 11px/600、关键几点 12px/600、分节 13px/700、一页读懂 12px/700）；`test/explain-quality.test.mjs`
补 10 条钉住标签与三条 `display` 拦截，全闸 209/209、11601 断言。

## L-024 最贵的字节往往不是代码，是写给人看的注释

入口包（`client.js`）只剩 3.5KB 余量时，第一反应是「又要拆模块了」。量一遍才发现：
`src/panel-kit.js` 的 CSS 144.6KB 源文本里，注释占 20.8KB——而这段 CSS 的 gzip 是 34.9KB，
去掉注释后 21.1KB。也就是说，**10.7KB gzip（占入口包预算的 8%）花在中文注释上**。

原因很直白：代码重复度高（同样的属性名、同样的类名前缀一遍遍出现），压缩器能吃掉；
注释是自然语言，每句都不同，压不动。所以要减体积，先找「写给人的字」，别先动架构。

**怎么改**：注释留在源码（它是「为什么这么写」的唯一记录，删了下次还得重新推理一遍），
在**构建期**剥。`tools/css-strip.mjs` 两条函数，`build-client` 与 `build-html` 共用一条路径，
所以产物自检「client.js 与源码一致」照样成立——它比的是「重建结果 == 现有产物」，重建也走这条路径。

**踩过的两个细节**：
- 剥注释不能只用正则：`content:"/*"` 会被误伤。按字符扫，遇到引号就整段吃掉字符串。
- 注释原地要留一个空格：`a/**/b{}` 直接删成 `ab{}`，两条选择器粘成一条不存在的选择器，
  样式静默失效。留空格才是正确答案。

**下次怎么防**：
- 体积告急先问「源码里有多少字不参与运行」：注释、帮助文案、示例、表格列名。
  跑一句 `工具` 就能量：注释占多少 raw、占多少 gzip（本例 raw 14%、gzip 31%）。
- 剥离类改动必须配「纯净度 + 安全边界 + 体积余量」三组断言：字符串里的标记不误伤、
  花括号配平（少一个会把后面整段样式吞掉）、余量 ≥10KB（别又回到「改一行就破线」）。
- 拆文件之前先数「有多少测试把它当一段自包含脚本 eval」。本例一百多份，拆开等于把
  「源码即脚本」换成「拼接器正确」——那不是一个更好的假设，只是换了个地方出错。

**实测**：client.js gzip 127525 → 113672（余量 3.5KB → 17.4KB），页面 1872.1 → 1863.5 KB，
CSS 花括号 1575 配平，`test/css-strip.test.mjs` 15 条，全闸 210/210、11616 断言。
